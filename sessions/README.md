# sessions/ — 세션별 묶음 (프로그램 1건 = 폴더 1개)

> 공통 파일(루트·`requirements/`·`harness/`·`context/`·`practice/`·`examples/`)은 전 세션이 공유한다.
> 세션 중에 생기는 작성본·산출물은 이 폴더 아래 `세션 폴더 1개`에 모아둔다.
> 폴더가 세션의 단일 진실 공급원(single source of truth)이다.

## 설계 의도 — 저장소는 공유하고, 세션으로 구분한다

프로그램을 만드는 세션은 **같은 저장소를 계속 공유하며 쌓인다.** 세션마다 저장소를 새로 만들지 않는다.
쌓이는 것과 섞이는 것은 다르므로, 아래 두 축으로 분리한다.

| 축 | 내용 |
|---|---|
| **쌓인다 (누적)** | 완료된 세션 폴더는 지우지 않고 계속 남는다. 하네스 개선분(`practice/`·`HARNESS.md` 등)도 누적된다 |
| **구분된다 (격리)** | 세션 산출물은 자기 폴더 안에만 둔다. 새 세션이 이전 세션 폴더의 값을 끌어오지 않는다 |

즉 **보관은 누적, 참조는 격리**다. 세션 간 지식 전달 경로는 `practice/` 하나로 고정한다.

## 1. 누적 경로 (브랜치 운영)

| 브랜치 | 역할 |
|---|---|
| **누적 브랜치** — 현재 `cursor/sap-gui-abap-vibe-coding-beca` | 확정된 하네스 + 완료된 세션 폴더가 쌓이는 기준선. 새 세션은 **항상 여기서 분기**한다 |
| **세션 브랜치** — 세션마다 1개 | 그 세션의 작업만 담는다. PR 대상은 누적 브랜치 |

```
누적 브랜치 ──┬─ 세션 브랜치 A ─ PR ─ 머지 ─┐
              │                              ↓
              └─────────── 누적 브랜치(세션 A 반영) ──┬─ 세션 브랜치 B ─ PR ─ 머지 ─→ …
```

### 세션 종료 시 반드시 하는 일

1. 세션 브랜치를 push하고 **PR 대상을 누적 브랜치로** 지정한다.
2. 아래 §4 색인 표에 **자기 세션 행 1줄을 추가**한다.
3. Handover `완료` 확인을 받은 뒤 **PR을 머지**한다. 머지하지 않으면 다음 세션에서 보이지 않는다.

머지되지 않은 세션 브랜치가 남아 있으면, 그 세션의 산출물과 하네스 개선분은 **다음 세션에 전달되지 않는다.**
PR이 열린 채 방치된 브랜치는 누적에서 빠진 상태이므로, 세션 시작 시 열린 PR이 있는지 확인한다.

### 누적에서 일부러 빼는 경우

분석·실험처럼 하네스의 일부가 아닌 산출물은 별도 브랜치에 두고 **PR을 만들지 않는다.**
그 경우 `.cursorignore` 에 경로를 등록하고, 라우터 문서(이 파일·`SKILL.md`·`AGENTS.md`)에서 링크하지 않는다.
누적에서 빠진다는 뜻이므로, 그 선택은 사용자가 명시적으로 지시할 때만 한다.

## 2. 폴더 규칙

- 이름: `YYYYMMDD-프로그램명` (예: `20260928-ZMM_PR_LINK_ALV01`)
- 날짜는 **세션 시작일**로 고정한다. 세션이 여러 날에 걸쳐도 폴더명을 바꾸지 않는다.
- 같은 프로그램을 다시 손대면 **새 폴더를 만들지 않고** 기존 폴더에 이어 쓰고 변경 이력에 날짜를 남긴다.
- 1건당 파일 구성 (해당 단계까지만 채운다, 빈 파일은 만들지 않는다):

| 파일 | 원본 템플릿 | 작성 시점 |
|---|---|---|
| `00-intake.filled.md` | `requirements/00-intake.md` + `00-intake-prompt.md` | 접수 시 (인터뷰면 답변 정리본) |
| `08-demo.filled.md` | `requirements/08-demo.md` | Gate D 텍스트 컨펌 시 |
| `demo-s1.png` / `demo-s2.png` | AI 생성 데모 이미지 | Gate D-2 이미지 재검증 시 |
| `09-fieldmap.filled.md` | `requirements/09-fieldmap.md` | Gate F 승인 시 |
| `spec.md` | Gate 2 스펙 확정안 | Gate 2 승인 시 |
| `code.abap` | Gate 3 산출물 | 코드 제공 시 (SE38 복붙본과 동일) |
| `screen-<화면번호>.md` | `practice/screen-text-detail.md` §A | Dynpro(SE51)가 생기는 산출물일 때 |
| `text-elements.md` | `practice/screen-text-detail.md` §B | 선택화면·텍스트 요소가 있을 때 |
| `ddic-request.md` / `ddic-probe.abap` | `context/ddic-collect.template.md` | 실측 회수가 필요할 때 (`practice/user-input-catalog.md` §3) |
| `verify.md` | V-1~V-4 답변 정리 | Verify 진행 시 |
| `errors.md` | 다건 Syntax 오류 목록 (V-3b 양식, 위에서부터 1건씩 순차 수정) | 오류 2건 이상 시 |
| `handover.md` | H-1 답변 + 이관 묶음 | Handover 시 |

## 3. 수정 범위 — 한 세션이 건드릴 수 있는 곳

| 영역 | 허용 범위 |
|---|---|
| `sessions/<자기 폴더>/` | 자유롭게 생성·수정 |
| `sessions/<다른 세션 폴더>/` | **읽기만. 수정·삭제 금지** |
| 이 파일의 §4 색인 | 자기 세션 행 1줄 추가·자기 행의 상태 갱신만 |
| `practice/`·`HARNESS.md`·`SKILL.md`·`AGENTS.md` 등 공통 | **추가·보강만.** 다른 세션이 남긴 패턴 행·규칙 삭제 금지 |
| `context/system-context.filled.md` | 시스템 실측값이 바뀌었을 때 갱신 (값의 출처 세션을 함께 적는다) |
| `requirements/` 템플릿 | 양식 자체의 결함을 고칠 때만. 특정 세션 사정을 양식에 박지 않는다 |

공통 자산에 추가할 때는 **출처 세션을 함께 남긴다.** `practice/error-patterns.md` 의 `출처 세션` 칼럼이 그 장치다.
그래야 나중에 "이 규칙이 왜 생겼나"를 해당 세션 폴더에서 되짚을 수 있다.

### 세션 간 참조 규칙

- **기본: 참조하지 않는다.** 새 세션은 이전 세션 폴더의 값(테이블·필드·스펙)을 새 코드에 끌어오지 않는다.
  요구사항이 다른데 끌어오면 조용히 오염되고, 사용자가 확인하지 않은 값이 코드에 들어간다.
- **지식 전달은 `practice/` 로만** 한다. 다음 세션에서도 같은 답이 나올 것만 패턴으로 승격한다 (V-3 규칙).
- **예외: 사용자가 지목하면 읽는다.** "`20260928` 세션의 ○○를 참고하라" 처럼 명시적으로 지목하면 그 폴더를 열람한다.
  이 예외가 성립하려면 **§4 색인이 최신이어야 한다.** 색인 갱신이 누적의 실질적인 가치다.

## 4. 보관 중인 세션 (색인)

> 세션 종료 시 자기 행을 추가한다. 이 표가 사용자가 과거 세션을 지목할 수 있는 유일한 입구다.

상태 표기: `진행 중 (게이트명)` / `완료` / `완료 (미검증 n건)` — 미검증이 있으면 건수를 드러내고 해당 세션 `verify.md` 에 목록을 둔다 (PROC-008).

| 세션 폴더 | 프로그램 | 유형 | 상태 | 남긴 패턴 |
|---|---|---|---|---|
| `20260928-ZMM_PR_LINK_ALV01/` | PR 연결정보 일괄 조회 | 01 ALV (SE38) | 완료 (Verify·Handover 완료) | ERR-005, ERR-006, MSG-002, PROC-001 |
| `20260930-ZMM_STOCK_TREE01/` | 법인/플랜트별 재고 현황 트리 조회 | 01 ALV 트리 (SE38 + SE51 화면 0100) | **완료 (미검증 6건)** — 활성화·T1 데이터 조회 통과. 사용자 지시로 Gate 4 조기 종결, 미검증 항목은 `verify.md` §4 | ERR-007, ERR-008, API-001, PROC-003 ~ PROC-008 |

패턴 ID의 내용은 `practice/error-patterns.md` 에 있다. `공통(HARNESS 대응표)` 출처 패턴(ERR-001~004, MSG-001, PROC-002)은 특정 세션 산출이 아니다.

## 5. 세션 시작 시 (AI용)

1. **누적 브랜치에서 분기**한다. 열린 PR이 남아 있으면 먼저 사용자에게 알린다 (§1).
2. `practice/error-patterns.md` 와 `practice/user-input-catalog.md` 를 읽는다. 세션 폴더는 읽지 않는다 (§3 참조 규칙).
3. 세션 폴더를 새로 만든다. 기존 세션 폴더의 값을 새 코드에 끌어오지 않는다.
4. 각 게이트 승인마다 해당 파일을 그때그때 기록한다 (마지막에 몰아서 쓰지 않는다).
5. 오류가 회수되면 `practice/error-patterns.md` 에 패턴으로 승격할지 판단한다 (V-3 규칙). 승격 시 `출처 세션` 을 적는다.
6. Handover 완료 시 §4 색인에 자기 행을 추가하고 PR을 머지한다.
