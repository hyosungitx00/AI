## §2 테이블·조인·로직 ★

### 확정된 테이블 (I-6 사용자 답변)

| 테이블 | 용도 |
|---|---|
| `MARA` | 자재 마스터 — 자재유형·자재그룹·기본단위 |
| `MARD` | 저장위치 재고 |
| `MARC` | 자재의 플랜트 데이터 |
| `MAKT` | 자재 내역 |

- `MARC` 는 현재 화면에 대응하는 출력 항목이 없다. 필요 용도(예: 플랜트 단위 자재 속성 필터)를 Gate F에서 확인하고, 쓰지 않으면 조회 대상에서 제외한다.

### 미확정 테이블 `[확인필요]` — `ddic-request.md` 회신 대기

| 용도 | 추측 | 비고 |
|---|---|---|
| 판매오더 재고 | `MSKA` | 참조 = 판매문서 + 품목 |
| 프로젝트 재고 | `MSPR` | 참조 = WBS 요소 |
| 고객 특별재고 | `MSKU` | 참조 = 고객 |
| 공급업체 위탁·반환포장 | `MKOL` | 참조 = 공급업체 (+ 저장위치) |
| 공급업체 보유 사급 재고 | `MSLB` | 참조 = 공급업체, 저장위치 없음 |
| 재고 평가 | `MBEW` (S/4 `NSDM_V_MBEW` 계열) | 산출 기준 미정 |
| 플랜트 → 회사코드 | `T001W` → `T001K` → `T001` | |
| 저장위치 명칭 | `T001L` | |

- S/4HANA는 위 재고 테이블군이 호환 뷰(`NSDM_V_*`)로 대체됐다. 확인 전에는 코드에 넣지 않는다.

### 조회 순서 (성능 설계 초안)

1. 선택화면 회사코드 범위 → 플랜트 목록 확정 (`T001` → `T001K` → `T001W`). 플랜트 입력이 있으면 교집합.
2. 플랜트 목록이 비면 0건 메시지 후 종료 (전사 조회 방지).
3. 자재 조건(자재번호·자재유형·자재그룹) → `MARA` 로 자재 목록 선별.
4. 확정 플랜트 + 자재로 저장위치 재고 조회 (`MARD`).
5. `특별재고 포함` 체크 시 특별재고 테이블을 유형별로 조회.
6. `금액 표시` 체크 시 평가 데이터 조회.
7. 자재내역(`MAKT`)·조직 명칭(`T001W`·`T001L`) 텍스트 보강.
8. 트리 노드 구성 + 소계 계산(A안) → `CL_GUI_ALV_TREE` 표시.

- `FOR ALL ENTRIES` 사용 시 직전 `IF ... IS NOT INITIAL` 빈 테이블 체크 필수 (`SKILL.md` §3.4).
- 루프 내 `SELECT SINGLE` 금지 — 텍스트는 사전 수집 후 해시 테이블 조회.
- 모든 DB I/O 직후 `SY-SUBRC` 체크 (PROC-002).

### 집계·정렬

- 소계: A안 — 노드 하위 기본단위가 모두 동일하면 수량 4열 소계 표시 + 그 단위 표시, 2종 이상이면 수량 공란 + 단위 "혼재" + 평가액만 합산.
- 정렬: 회사코드 → 플랜트 → 재고구분(저장위치 재고 먼저) → 저장위치·특별재고유형 → 자재번호 오름차순.
- 최초 펼침: 1단·2단까지 펼치고 3단 이하는 접힘 (`[추정]`, Gate F에서 확정).

## §3 구현 방식 ★ (AI 제안 + 사용자 확정)

- 프로그램 유형 확정 ★: [x] 01 ALV(SE38) — 조회 전용, I-4에서 확정
- 오브젝트명(가안) ★: `ZMM_STOCK_TREE01` (네이밍 규칙 `Z`+모듈약어 MM)
- ALV 방식: [ ] SALV [ ] REUSE [x] GUI 컨테이너 — `CL_GUI_ALV_TREE`
  - 근거: 계층 트리에 수량·금액 열을 함께 붙여야 한다. `CL_SALV_TABLE`·`REUSE_ALV_GRID_DISPLAY` 는 계층 트리를 지원하지 않는다. `CL_SALV_TREE` 는 트리는 되지만 열 제어·소계 표현이 제한적이다.
  - 부수 조건: `CL_GUI_ALV_TREE` 는 컨테이너가 필요하므로 결과화면용 화면(Dynpro) 1개와 PBO/PAI 모듈이 추가된다. SE38 실행가능 리포트에 화면 1개를 포함하는 구조이며, Module Pool로 바뀌는 것은 아니다.
  - **Gate F 확인 필요**: 이 구조를 수락할지, 아니면 트리를 포기하고 평면 ALV + 소계(`CL_SALV_TABLE`)로 단순화할지.
- 메시지 클래스: [ ] 신규 `ZMM_MSG` 생성 [ ] 기존 사용 [x] 미정 — Gate 2에서 확정. SE91 생성을 피하려면 텍스트 리터럴 방식으로 대체 가능 (MSG-002).
- 권한 오브젝트: `[모름-SU53 TRACE 예정]` (I-7 20번 답변 `모름`)
  - 코드에는 `AUTHORITY-CHECK` 호출 지점을 만들어 두고 오브젝트명은 `"! TODO(SU21/SU53): 오브젝트명 확정 필요` 주석으로 격리한다 (`SKILL.md` §3.4, MSG-001).
  - 체크 지점 2곳: ① 회사코드·플랜트 조회 권한 ② 평가액 조회 권한(금액 표시 옵션 ON일 때만).
  - 활성화 후 V-1~V-2 단계에서 SU53 TRACE 결과를 받아 오브젝트명을 확정한다.
- 비정상 처리 (I-7 21번 확정)
  | 상황 | 처리 |
  |---|---|
  | 조회 0건 | `S` 안내 메시지 "조회 조건에 해당하는 재고가 없습니다" 후 선택화면 유지 |
  | 회사코드 미입력 | `E` 메시지 + 커서를 회사코드 필드로 이동 (전사 조회 차단, ERR-005) |

  | 회사코드로 플랜트를 못 찾음 | 0건과 동일 처리 (`S` 메시지) |
