# DDIC 확인 요청서 — SE11에서 확인해 주실 항목

> 세션: `20260930-ZMM_STOCK_TREE01` / 작성일: 2026-09-30
> 근거: `SKILL.md` §3.1 (환각 금지 — 테이블·필드는 사용자가 준 것만 사용), `context/ddic-collect.template.md`
> I-6 답변에서 `MARA` · `MARD` · `MARC` · `MAKT` 는 확정받았다. 아래 `[확인필요]` 항목은 **추측값이며 확인 전에는 코드에 넣지 않는다.**

## 왜 확인이 필요한가

S/4HANA는 재고 데이터 모델이 ECC와 다르다. 저장위치 재고·특별재고의 집계 테이블(`MARD`·`MSKA` 등)은 수량 필드가 전표 기반 모델(`MATDOC`)로 이동하고 호환 뷰(`NSDM_V_*` 계열)로 대체됐다. 시스템에 DDIC 리다이렉트가 적용돼 있으면 기존 테이블명으로도 조회되지만, 그렇지 않으면 활성화 또는 실행에서 막힌다. AI는 시스템에 접속할 수 없어 어느 쪽인지 판별할 수 없다.

## 가장 빠른 확인 방법 (권장)

`SE38` → `RM07MLBS` (MB52의 실제 프로그램) 표시 → 재고를 읽는 `SELECT` 구문 부분을 그대로 복사해 전달. 그 시스템에서 실제로 동작하는 이름이므로 추측이 아닌 확정값이 된다. `MMBE`는 `RMMMBESTN` 을 확인한다.

## 확인 항목 1 — 저장위치 재고 (확정 테이블 `MARD`)

| 확인 | 내용 |
|---|---|
| ① | `MARD`의 가용(비제한사용)·품질검사·보류 수량 필드명 3개 |
| ② | `SE16N`에서 `MARD`를 조회했을 때 위 수량 필드에 **실제 값이 들어 있는지** (S/4에서 값이 비면 호환 뷰를 써야 한다는 신호) |

```markdown
### MARD
- 가용(비제한사용) 수량 필드: ____
- 품질검사 수량 필드: ____
- 보류(제한사용) 수량 필드: ____
- SE16N 값 존재: [ ] 값 있음  [ ] 전부 0·공백 (→ 호환 뷰 필요)
```

## 확인 항목 2 — 특별재고 4종 `[확인필요]`

I-6에서 "특별재고 전부"로 확정됐다. 특별재고는 유형별로 테이블이 갈라지며, 아래는 **AI 추측값**이다. 존재 여부와 수량 필드명을 확인해 주십시오.

| 특별재고 유형 | 추측 테이블 `[확인필요]` | 참조 키 | 확인란 |
|---|---|---|---|
| E 판매오더 재고 | `MSKA` | 판매문서 + 품목 | 존재: [ ] O [ ] X / 수량필드: ____ |
| Q 프로젝트 재고 | `MSPR` | WBS 요소 | 존재: [ ] O [ ] X / 수량필드: ____ |
| V·W 고객 특별재고 (위탁·반환포장) | `MSKU` | 고객 | 존재: [ ] O [ ] X / 수량필드: ____ |
| K·M 공급업체 위탁·반환포장 재고 | `MKOL` | 공급업체 + 저장위치 | 존재: [ ] O [ ] X / 수량필드: ____ |
| O 공급업체 보유 사급 재고 | `MSLB` | 공급업체 | 존재: [ ] O [ ] X / 수량필드: ____ |

- `MSLB`(공급업체에 있는 사급 재고)는 우리 플랜트의 저장위치가 없으므로, 트리에서 저장위치 단 없이 특별재고 유형 단 바로 아래에 자재가 붙는다. 포함 여부를 함께 판단해 주십시오.
- 각 테이블에 특별재고 표시자 필드(`SOBKZ` 계열)가 있는지도 확인 대상이다.

## 확인 항목 3 — 평가액 `[확인필요]` (I-6 22번 답변: 모름)

기능 ⑥ 평가액 표시에 필요하다. 산출 기준도 함께 정해야 한다.

| 확인 | 내용 |
|---|---|
| ① | 자재 평가 테이블명 — 추측 `MBEW` (S/4 호환 뷰 `NSDM_V_MBEW` 계열) |
| ② | 금액 산출 기준 택 1 — (a) 이동평균가/표준가 × 조회 수량으로 계산 / (b) 평가 테이블의 재고 총액 필드를 그대로 사용 |
| ③ | 평가 단위가 플랜트인지 평가영역인지 (평가영역 = 플랜트 여부는 조직 설정에 따라 다르다) |
| ④ | 통화 필드 출처 — 회사코드 통화(`T001`)를 쓰는지 |

- (a)는 조회 수량과 금액이 항상 일치하지만 재고 평가 관점에서는 근사값이다. (b)는 회계 장부와 맞지만 조회 조건으로 걸러낸 수량과 금액이 어긋날 수 있다. 특별재고는 평가가 별도 테이블로 갈라지는 경우가 있어(판매오더 재고·프로젝트 재고 평가) 추가 확인이 필요하다.

## 확인 항목 4 — 조직 구조 `[확인필요]`

트리 최상위인 법인(회사코드)은 재고 테이블에 직접 들어 있지 않고 플랜트를 거쳐 연결된다.

| 확인 | 추측 경로 `[확인필요]` |
|---|---|
| 플랜트 → 회사코드 | `T001W`(플랜트, 평가영역) → `T001K`(평가영역 → 회사코드) → `T001`(회사코드명) |
| 저장위치 명칭 | `T001L` |
| 자재 내역 | `MAKT` (로그온 언어) — I-6에서 확정 |
