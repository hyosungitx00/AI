## §0 선결 쟁점 — DDIC 가정 개수가 저장소 규칙을 초과함

사용자 선택: **B안 (추측값으로 코드를 받고 SE38 구문 검사로 검증)**, 2026-10-01.

### 해결안 — DDIC 점검 리포트로 가정을 0건으로 만든다

`ddic-probe.abap` (20줄 남짓, 조회 전용)을 SE38에 붙여 한 번 실행하면, 후보 테이블의 **존재 여부 + 실제 수량(QUAN)·금액(CURR)·키 필드명**이 목록으로 출력된다. 그 출력을 그대로 주시면 위 7건이 전부 확정값으로 바뀐다.

- SE11을 화면마다 클릭할 필요가 없고, 복붙 1회 + 실행 1회로 끝난다. 테스트를 직접 하시겠다는 I-8 답변과도 맞는다.
- 이 리포트는 DDIC 메타데이터만 읽고 업무 데이터를 건드리지 않는다. 오브젝트를 만들지도 않는다.
- 점검 결과가 오면 본 프로그램은 `확인필요` 0건으로 생성된다 (규칙 충돌 해소).

**대안**: 위 절차를 생략하고 추측값 그대로 코드를 원하시면, 이번 건에 한해 `HARNESS.md` §3.2의 3개 초과 금지 규칙을 면제한다는 지시를 주시면 그대로 진행한다. 그 경우 코드의 해당 줄마다 `"! [확인필요]` 주석을 달고, 구문 검사에서 드러나는 오류를 V-3b 절차(첫 1건부터 순차 수정)로 잡는다.

## §5 트리 구성 규칙

### 계층 5단

| 단 | 노드 키 | 표시 |
|---|---|---|
| 1 | 회사코드 | 코드 + 회사명 |
| 2 | 플랜트 | 코드 + 플랜트명 |
| 3 | 재고 구분 | `저장위치 재고` / `특별재고` (프로그램 생성 가상 노드) |
| 4 | 저장위치 또는 특별재고 유형 | 코드 + 명칭 |
| 5 | 자재 (+ 특별재고는 참조 조합) | 자재번호 + 자재내역 |

- 저장위치가 없는 특별재고 유형은 4단 아래에 자재가 바로 붙는다.
- 특별재고 구간의 5단 노드는 **자재 + 참조 조합 1건 = 1행**. 같은 자재가 참조 2건에 걸리면 2행으로 분리한다.
- 정렬: 회사코드 → 플랜트 → 재고구분(저장위치 재고 먼저) → 저장위치·유형 → 자재번호 오름차순
- 최초 펼침: 1단·2단까지 (`[추정]` U-2)

### 소계 알고리즘 (A안 확정)

```text
노드 소계 계산:
  하위 자재의 기본단위 집합을 수집한다
  IF 단위 종류 = 1
     수량 4열(가용·품질검사·보류·합계) 합산 표시 + 단위 표시
  ELSE
     수량 4열 공란 + 단위 열에 "혼재" 표시
  ENDIF
  평가액은 단위와 무관하게 항상 합산 (통화가 1종일 때)
```

- 통화가 2종 이상 섞이면 평가액도 동일 규칙으로 공란 + "혼재" 처리한다 (해외 법인 혼합 조회 대비).
