## 1. SE93 — T-code 생성 (선택)

| 항목 | 값 |
|---|---|
| 트랜잭션 코드 | `[미정]` — 예: `ZMM_STKTREE` |
| 시작 오브젝트 | 프로그램 및 화면(대화 트랜잭션) 또는 프로그램 (리포트 트랜잭션) |
| 프로그램 | `ZMM_STOCK_TREE01` |
| 화면 번호 | `1000` (선택화면. 리포트 트랜잭션으로 등록하면 생략) |

리포트 트랜잭션(`시작 오브젝트 = 프로그램 및 선택화면`)으로 등록하는 쪽이 간단하다. 선택화면 1000 이 먼저 열리고, 실행하면 화면 0100 트리로 넘어간다.

## 2. 권한 목록 (SU21/PFCG 등록용)

**미확정 상태다.** 코드에 체크 지점만 만들고 오브젝트명을 비워 두었다.

| 체크 지점 | 코드 위치 | 추정 오브젝트 `[확인필요]` | 필드 | 값 |
|---|---|---|---|---|
| ① 재고 조회 | `f_check_authority` 주석 ① | `M_MSEG_WWA` 계열 | `ACTVT` / `WERKS` | `03` / 입력 플랜트 |
| ② 평가액 조회 | `f_check_authority` 주석 ② (`P_VAL = X` 일 때만) | `[확인필요]` | `[확인필요]` | — |

### 확정 절차

1. 권한이 부족한 사용자 ID로 실행해 실패를 유발한다.
2. 실패 직후 `SU53` 을 실행한다. 마지막으로 실패한 권한 체크가 오브젝트·필드·값까지 표시된다.
3. 그 값으로 `f_check_authority` 의 `TODO(SU21/SU53)` 주석 2지점을 실제 `AUTHORITY-CHECK` 문으로 교체한다.
4. 실패 메시지 문구는 이미 주석에 준비되어 있다 — `'해당 회사코드/플랜트 조회 권한이 없습니다.'`

표준 조회(MMBE·MB52) 권한이 이미 부여된 사용자라면 동일 오브젝트를 재사용하는 것이 가장 안전하다.

## 3. TR 초안 (이송 오브젝트 목록)

이송 순서가 중요하다. **화면·상태·타이틀이 프로그램보다 먼저**여야 활성화가 깨지지 않는다.

| 순서 | 오브젝트 유형 | 이름 | 비고 |
|---|---|---|---|
| 1 | 프로그램 (R3TR PROG) | `ZMM_STOCK_TREE01` | 본체. 패키지 `[미정]` |
| 2 | Dynpro 화면 | `ZMM_STOCK_TREE01` 화면 `0100` | 커스텀 컨트롤 `CC_TREE` + 종료 푸시버튼 |
| 3 | GUI 상태 | `STAT0100` | F3 `BACK` / Shift+F3 `EXIT` / F12 `CANC` |
| 4 | GUI 타이틀 | `TIT0100` | `&1` 치환 |
| 5 | 텍스트 요소 | 선택 텍스트 10건 + 프로그램 제목 | **언어 종속.** 이송 시 언어 포함 확인 |

- 화면·GUI 상태·타이틀·텍스트 요소는 프로그램의 **하위 오브젝트**라서 프로그램 TR 에 자동 포함되는 것이 일반적이다. `SE80` → 프로그램 → 오브젝트 목록에서 전건 포함을 확인한다.
- SE91 메시지 클래스는 **사용하지 않는다** (텍스트 리터럴 방식, MSG-002). 이송 대상 없음.
- T-code 를 만들었다면 `R3TR TRAN` 1건이 추가된다.

### 검증 T-code (이송 후)

1. `SE38` → `ZMM_STOCK_TREE01` → 선택 텍스트 10건이 **한글로** 표시되는지 확인 (언어 미이송 시 영문·공란이 된다).
2. `S_BUKRS` 에 대표 회사코드 입력 → F8 → 트리 표시 확인.
3. F3 / Shift+F3 / F12 동작 확인 (GUI 상태 미이송 시 죽는다).

## 4. 운영 주의사항

### 4.1 반드시 선행해야 하는 것

| 항목 | 내용 |
|---|---|
| 패키지 확정 | `$TMP` 는 이송 불가. 실 패키지 지정 필수 |
| SU53 권한 확정 | §2. 지금 상태는 **권한 체크가 비어 있어 누구나 전 법인 재고를 볼 수 있다** |
| `verify.md` §4 미검증 항목 | T1-b(금액)·T2(0건)·T3(권한·검증)·T3-b(MM03) 미확인 |

권한 체크가 비어 있는 점이 가장 중요하다. 재고 수량과 평가액은 법인별로 열람 범위가 갈리는 정보이므로, **SU53 확정 전에는 운영 클라이언트에 이송하지 않는 것을 권고한다.**

### 4.2 성능

| 항목 | 값 | 근거 |
|---|---|---|
| 실측 재고 행 | 689,319 행 (회사코드 1건, 플랜트 4개) | 2026-10-01 사용자 실측 |
| 실측 표시 행 | 7,339 행 | 같음 |
| 기본 상한 | `P_MAXROW = 10000` | 실측 7,339 수용 + 여유 |
| 상한 초과 시 | **자르지 않고 막는다.** 조건을 좁히라고 안내 | 자르면 상위 노드 소계가 왜곡된다 (PROC-007) |

트리 노드를 1건씩 만들기 때문에 표시 행이 많으면 화면이 열리지 않는 것처럼 느려진다. 상한을 올릴 때는 10,000 단위로 올리며 체감 속도를 확인하는 것을 권고한다.

### 4.3 데이터·개인정보

| 항목 | 처리 |
|---|---|
| 특별재고 참조 (고객·공급업체) | **번호만 표시.** 이름 조회·표시 없음 (I-7 답변으로 확정) |
| 하드코딩 | 없음. 회사코드·플랜트 전부 선택화면 입력 |
| 통화·단위 | 자재 기본단위(`MARA-MEINS`), 금액은 회사코드 통화 가정 `[확인필요]` |

### 4.4 S/4HANA 재고 모델 관련 잔존 위험

`MARD`·`MSKA` 등 집계 테이블을 직접 읽는다. 2026-10-01 DDIC 점검 프로그램 실행으로 **해당 시스템에서는 값이 조회됨을 확인**했으나, 시스템 업그레이드나 다른 클라이언트에서는 호환 뷰(`NSDM_V_*`)로 바꿔야 할 수 있다.

업그레이드 후 수량이 전부 0 으로 나오면 이 원인이다. 점검 방법은 `ddic-probe.abap` 재실행이다.
