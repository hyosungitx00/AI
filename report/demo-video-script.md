# 시연 영상 시나리오 (부록 C)

> 총 3분 00초 구성. 평가 기준 "완성도 — 리포트 및 영상의 구성과 전달력"에 대응한다.
> **촬영 원칙**: 실제 화면만 쓴다(연출 금지). SAP GUI 화면은 담당자가 직접 녹화해야 하고,
> 저장소·Cursor 화면은 이 저장소에서 그대로 재현된다.

## 전체 구성

| # | 장면 | 시간 | 누적 | 화면 | 목적 |
|---|---|---|---|---|---|
| 1 | 문제 제기 | 0:00~0:25 | 0:25 | PPT 1장 | 왜 일반 바이브 코딩이 안 되는가 |
| 2 | 인터뷰 접수 | 0:25~0:55 | 0:55 | Cursor 대화 | 담당자가 몰라도 설계가 진행됨 |
| 3 | 화면 컨펌 | 0:55~1:20 | 1:20 | 데모 이미지 S1/S2 | 코드 전에 요구사항을 확정 |
| 4 | 자동 점검 | 1:20~2:00 | 2:00 | 터미널 | **핵심 장면** — 기계가 결함을 잡는다 |
| 5 | SAP 활성화 | 2:00~2:35 | 2:35 | SAP GUI | 데모가 아니라 실제 동작 |
| 6 | 학습 구조·효과 | 2:35~3:00 | 3:00 | PPT 2장 | 오류가 자산이 되는 경로 + 수치 |

## 장면별 상세

### 장면 1 — 문제 제기 (0:00~0:25)

- **화면**: 제목 슬라이드 → 제약 4가지 슬라이드
- **내레이션**:
  > "SAP ABAP 개발에는 생성형 AI를 그대로 쓸 수 없습니다. AI는 SAP에 접속할 수 없어서,
  > 만든 코드를 사람이 손으로 옮겨 활성화해야 합니다. 테이블 이름을 하나라도 지어내면
  > 활성화가 실패하고 작업은 처음으로 돌아갑니다. 그래서 이 과제는 AI에게 자유를 주는 대신,
  > 관문을 세우는 방식으로 접근했습니다."

### 장면 2 — 인터뷰 접수 (0:25~0:55)

- **화면**: Cursor 채팅. `[신규 프로그램 요구사항 인터뷰 시작 요청]` 입력 → AI가 3문항씩 질문
- **강조 표시**: 담당자가 테이블 질문에 `[모름]`으로 답하는 장면에 자막 처리
- **내레이션**:
  > "담당자는 양식을 작성하지 않습니다. AI가 한 번에 세 문항씩 묻고, 모르는 항목은 모름이라고
  > 답하면 AI가 제안으로 메우고 추정 표시를 붙입니다. 실제 1호 과제에서도 담당자는 테이블명을
  > 모른 상태로 설계를 끝까지 진행했습니다."

### 장면 3 — 화면 컨펌 (0:55~1:20)

- **화면**: `sessions/20260928-ZMM_PR_LINK_ALV01/` 의 데모 이미지(S1 선택화면 / S2 ALV 결과)
- **강조**: 1차 반려(합성형) → 2차 분리형 컨펌 흐름을 좌우 비교로 제시
- **내레이션**:
  > "코드를 만들기 전에 화면을 먼저 확인받습니다. 1호 과제에서는 선택화면과 결과를 한 화면에
  > 합쳐 그렸다가 반려됐습니다. 코드 생성 전이었기 때문에 수정 비용은 그림 한 장이었습니다.
  > 이 교훈은 공용 패턴으로 등록되어 이후 모든 데모에 적용됩니다."

### 장면 4 — 자동 점검 (1:20~2:00) **핵심**

- **화면**: 터미널. 아래 명령을 순서대로 실제 실행
- **강조**: 오류 2건이 줄번호·근거·처방과 함께 출력되는 순간 일시 정지 + 확대

```bash
# ① 세션 폴더 준비
tools/new_session.sh ZSD_DEMO_ALV01

# ② 코드 골격 복제
cp templates/abap/01-alv-salv.abap sessions/<폴더>/code.abap

# ③ 흔한 결함 2종 주입 (TABLES 선언 삭제 + SY-SUBRC 분기 삭제)

# ④ Gate 3 자동 점검 — 여기가 핵심 장면
python3 tools/abap_check.py sessions/<폴더>/code.abap
```

- **기대 출력** (실측):

```text
  ERROR   L47    CHK-005  사전 필드 `VBAK-...`를 참조하는데 `TABLES vbak.` 선언이 없습니다.
                 근거 ERR-006 · 처방: 코드 상단에 `TABLES <테이블>.` 선언을 추가하십시오.
  ERROR   L92    CHK-004  SELECT 직후 `SY-SUBRC` 체크가 없습니다.
요약: 파일 1개 · 오류 2건 · 경고 0건
Gate 3 미통과 — 오류 0건이 될 때까지 코드를 사용자에게 제시하지 마십시오.
```

- **내레이션**:
  > "코드가 담당자에게 전달되기 전에 점검기가 17개 규칙으로 검사합니다. 여기서는 실전에서 가장
  > 흔한 결함 두 개를 일부러 넣었습니다. 몇 번째 줄이 문제인지, 어떤 과거 오류 패턴에 해당하는지,
  > 무엇을 고쳐야 하는지가 함께 나옵니다. 오류가 0건이 아니면 코드는 전달되지 않습니다.
  > 걸리는 시간은 0.04초입니다."

### 장면 5 — SAP 활성화 (2:00~2:35)

- **화면**: SAP GUI 실제 녹화 — SE38 → `Ctrl+F2` Syntax Check(에러 0건) → F8 실행 → 선택화면(S1)
  입력 → ALV 결과(S2)
- **촬영 주의**: 실데이터가 보이면 모자이크 처리. 테스트 코드값만 사용
- **내레이션**:
  > "실제 시스템입니다. 구문 검사 오류 0건, 실행 후 선택화면과 ALV 결과가 정상 표시됩니다.
  > 1호 과제는 여기서 끝나지 않고 권한 확인과 이송 요청서까지 운영 이관을 완료했습니다.
  > 데모가 아니라 실제 업무에 적용된 건입니다."

### 장면 6 — 학습 구조·효과 (2:35~3:00)

- **화면**: 학습 구조 도식 슬라이드 → 핵심 수치 슬라이드
- **내레이션**:
  > "이 과제의 핵심은 코드 생성 속도가 아니라 축적입니다. 한 번 겪은 활성화 실패는 패턴으로
  > 등록되고, 기계 점검 규칙이 되고, 코드 골격에 선반영됩니다. 1호 과제의 실패 하나가 지금은
  > 코드가 만들어지는 순간부터 막혀 있습니다. 현재 패턴 10건, 점검 규칙 17건이 축적되어 있고,
  > 같은 팀의 다른 담당자는 저장소를 열기만 하면 이 자산을 그대로 사용합니다."

## 촬영 체크리스트

- [ ] SAP GUI 화면에 실데이터·개인정보 노출 없음 (테스트 코드값만)
- [ ] 시스템 정보(호스트·클라이언트·사용자 ID) 노출 없음
- [ ] 장면 4의 터미널 출력은 연출이 아니라 실제 실행 결과
- [ ] 장면 3의 데모 이미지는 세션 폴더의 실제 산출물
- [ ] 자막으로 핵심 수치 3개 노출: 오류 1건→0건 / 점검 0.04초 / 패턴 10건·규칙 17건
- [ ] 총 길이 3분 이내, 각 장면 전환에 구분 자막

## 장면 4 재현 명령 (촬영 전 리허설용)

```bash
cd <저장소>
tools/new_session.sh ZSD_DEMO_ALV01
cp templates/abap/01-alv-salv.abap sessions/$(date +%Y%m%d)-ZSD_DEMO_ALV01/code.abap
# 편집기로 TABLES 선언 1줄과 SELECT 직후 IF sy-subrc 블록을 삭제
python3 tools/abap_check.py sessions/$(date +%Y%m%d)-ZSD_DEMO_ALV01/code.abap
# 촬영 후 정리
rm -rf sessions/$(date +%Y%m%d)-ZSD_DEMO_ALV01
```
