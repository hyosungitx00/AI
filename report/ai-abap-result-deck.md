# Cursor AI를 활용한 SAP GUI ABAP 바이브 코딩

AI 연구과제 결과 보고 | 2026-10-07 | 대상: SAP S/4HANA SE38·SE37

## 결론 — ABAP 코딩에 AI를 쓰면 훨씬 효율적이다

- 담당자는 **쓸 테이블조차 모르는 상태**에서 출발 → AI가 테이블 6개 제안
- AI가 **156줄 ABAP + 테스트 케이스 + 권한·이송 문서**까지 생성
- 결과: **활성화 오류 1건만**으로 완성, T1~T3 전부 통과, 운영 이관 완료
- 수작업이라면 SE11 조사 단계부터 시작해야 했던 일 → **AI 없이는 같은 기간 완료 곤란**

> 그리고 AI를 **그냥** 쓰는 것보다, 저장소로 **방향과 가이드**를 줄 때 효과가 더 커진다

| 비교축 | 내용 | 리포트 |
|---|---|---|
| **주축** | AI 미활용(수작업) → **AI 활용** | §4.1 · §4.4 |
| 보조축 | AI 단독 → **AI + 저장소 가이드** | §4.3 · §4.5 |

## 한 장 요약 — 두 축의 효과

**주효과 (AI 활용)**

| 지표 | 결과 |
|---|---|
| 실전 적용 | 프로그램 1건, 설계~활성화~운영 이관 전 구간 완료 |
| AI 생성 분량 | ABAP **156줄**(실효 122줄) + 테스트 3건 + 이관 문서 |
| 착수 조건 | 테이블·빈도·권한 **전부 `[모름]`** 상태에서 완료 |
| 활성화 품질 | 실효 122줄 중 Syntax 오류 **1건** → 수정 후 0건 |

**부가효과 (저장소 가이드)**

| 지표 | 결과 |
|---|---|
| 결함 발생률 | 가이드 전 AI 산출물 **2/2 결함** → 골격 기반 **0/3** |
| 품질 검증 | 수동 8항목 대조 → 명령 1회 17규칙 **0.04초** |
| 요구사항 반영 | 화면 목업을 **코드 생성 전** 컨펌 (1차 반려 → 교정) |
| 재발 방지 자산 | 오류 패턴 10건 · 점검 규칙 17건 · 코드 골격 3종 |

## 1. 과제 개요 — 대상 업무

- SAP 운영·개발 담당자의 **커스텀 ABAP 개발 업무**
- 주력 범위: 요청 빈도가 가장 높은 2개 유형으로 한정

| 유형 | 내용 | 트랜잭션 | 범위 |
|---|---|---|---|
| 01 ALV 리포트 | 선택화면 + 조회 + ALV 출력 | SE38 | 주력 |
| 03 Function Module | 재사용 로직, 배치 호출 대상 | SE37 | 주력 |
| 02 / 04~07 | Module Pool·Enhancement·Interface·Batch·Forms | SE80 등 | 확장(템플릿 보유) |

- 대표 요청: "여러 화면을 돌며 눈으로 맞춰 보던 정보를 한 화면에서 조회하게 해 달라"
- 실전 1호가 정확히 이 유형 — 구매요청(PR) 연결 정보 일괄 조회 ALV

## 2. 추진 배경 ① — 왜 AI를 도입했는가

- 조회성 리포트 1건에 담당자가 **요구사항~코드~테스트~이관** 전 과정을 혼자 수행
- 그중 상당 부분은 창의적 판단이 아닌 **정형 반복 작업**
  - ALV 뼈대, 선택화면 검증 로직, `SY-SUBRC` 처리, 엑셀 다운로드는 프로그램마다 거의 동일
- 더 큰 문제는 **착수 자체가 막히는 것**
  - 실전 1호: 담당자가 **어떤 테이블을 써야 하는지 몰랐음**
  - 수작업이면 SE11·업무 문서 **조사를 끝낸 뒤**에야 코딩 진입 가능

> AI는 이 조사 단계를 **"후보 제안 + 담당자 확인"** 으로 단축 → AI 도입의 1차 동기

## 3. 추진 배경 ② — 왜 저장소 가이드가 필요한가

SAP GUI 환경에서는 AI를 그대로 쓰면 효과가 깎입니다.

- **AI가 시스템을 볼 수 없다** — 접속·실행·디버깅 불가. 사람이 SE38에 손으로 옮겨 활성화
- **DDIC 환각이 치명적** — 필드명 하나를 지어내면 활성화 실패 → 오류 회수·수정·재복붙 왕복
- **릴리스별 문법 차이** — ECC 6.0 / NW 7.40 / 7.50 / S4에서 쓸 수 있는 문법이 다름
- **요구사항 오해가 늦게 드러남** — 코드 완성 후 "원하던 화면이 아니다" → 설계부터 재작업

> 핵심 질문은 "AI가 코드를 잘 쓰는가"가 아니라 **"한 번에 활성화되는 코드가 나오는가"**
> → 이 제약을 방치하면 복붙 왕복이 늘어 **AI 도입 효과가 상쇄됨**

## 4. 기존 업무 방식 — AI 미활용 (As-Is)

기준선은 **AI를 전혀 쓰지 않고 담당자가 전 과정을 수행하던 방식**입니다.

| 단계 | 수작업 시 담당자가 하던 일 | AI 활용 시 |
|---|---|---|
| 요구사항 정리 | 구두·메일 요청을 문서로 정리 | AI가 37문항 질문, 담당자는 답변만 |
| 테이블 조사 | SE11·업무 문서로 탐색 | AI가 후보 6개 제안 → 확인 |
| 조인·필드 설계 | 키 관계 파악, 연결표 작성 | AI가 연결표 초안 → 승인 |
| 코드 작성 | ABAP 전량 타이핑 | AI가 **156줄** 생성 |
| 테스트 설계 | 케이스·테스트값 작성 | AI가 T1~T3 작성 |
| 운영 이관 | 권한 조사, TR·잡 판단 | AI가 권한·TR 초안·판정 작성 |

- 담당자에게 남는 일은 **확인·승인·SAP 조작(복붙·활성화·실행)**
- **판단은 사람, 작성은 AI** 로 분담
- 담당자 / 빈도 / 1건 공수: **[실측 기입]** — 양식 `report/effect-worksheet.md`

## 5. 실패 비용 구조 — 게이트를 앞단에 집중시킨 이유

| 발견 시점 | 되돌아가는 범위 | 비용 |
|---|---|---|
| 요구사항 단계 | 질문 한 번 | 낮음 |
| 화면 컨펌 단계 | 화면 설계 재작성 | 낮음 |
| 스펙 단계 | 테이블·조인 재설계 | 중간 |
| 활성화 단계(Syntax) | 코드 수정 + 복붙 왕복 | 높음 |
| 운영 단계(성능·권한) | 장애 대응 + 재이송 | 매우 높음 |

- 오류를 **앞단에서 잡는 것**이 이 체계의 설계 목표

## 6. 개선 방법 — 두 단계로 진행했다

```text
[1단계] AI 도입
   수작업 전량 → AI가 설계 초안·코드·테스트·이관 문서 생성
   → 담당자는 확인·승인·SAP 조작만 수행
   → 효율은 올랐으나 활성화 실패·환각 위험이 남음

[2단계] 저장소로 방향·가이드 제공          ← 본 저장소의 역할
   요구사항: 37문항 인터뷰로 강제 확정 (Gate U/D/D-2/F)
   사실관계: DDIC 확정값만 사용, 모르면 [확인필요] (Gate 1)
   출력형식: 복붙 계약으로 생략 없는 완전 소스 고정
   품질검증: 17규칙 기계 점검으로 코드 제시 전 차단 (Gate 3)
   경험축적: 발생 오류를 패턴→규칙→골격으로 승격 (Gate 4)
   → AI 산출물이 "한 번에 활성화되는 코드"에 수렴
```

- 저장소는 목적이 아니라 **AI 출력 품질·요구사항 반영도를 끌어올리는 수단**
- 담당자는 Cursor로 저장소를 열고 **요청만** 하면 규칙이 자동 적용

## 7. 개선 방법 — 활용 AI 도구

| 도구 | 용도 |
|---|---|
| **Cursor AI** | 주 작업 환경. 저장소 규칙 자동 적용, 인터뷰·설계·코드 생성 |
| Cursor Cloud Agent | 저장소 구조 최적화·자동화 도구 개발 |
| 범용 LLM (ChatGPT·Claude) | 대체 수단. 프롬프트 조각 등록으로 동일 규칙 적용 |
| Python 3 (표준 라이브러리) | 자동 점검기 구동. 외부 패키지 불필요 |

- **SAP 시스템에는 어떤 도구도 설치하지 않음** — 기존 SE38/SE37 방식을 그대로 두고 앞단만 보강
- 시스템 영향도·보안 검토 부담 없음

## 8. 개선 방법 — 설계 원칙 3가지

- **DDIC 그라운딩** — 담당자가 확인해 준 값, 또는 과거 활성화로 실재가 증명된 값만 사용.
  모르면 추측 코드 대신 질문으로 되돌림. 가정 3건 초과 시 코드 생성 중단
- **릴리스 게이트** — 기준 `SAP_BASIS 750 / S/4HANA` 고정, 코드 상단 명시.
  보수 문법 필요 건만 ECC 호환으로 폴백
- **복붙 계약** — 완전 소스 1개 + 번호 매긴 복사 순서 + DDIC·메시지·T-code 정의서
  + T1~T3 테스트 표 + 오류 회수 양식. 담당자가 추가 판단 없이 그대로 옮길 수 있는 상태로만 전달

## 9. 개선 방법 — 진행 절차 9개 게이트

```text
[0]   사전준비 1회 ─ 릴리스·패키지·네이밍            │ Gate 0
[0.5] 인터뷰 설계 25문항 (한 턴 3문항, [모름] 허용)
        │ Gate U   AI 이해 내용 확인서 승인
        │ Gate D   화면 텍스트 목업 컨펌
        │ Gate D-2 화면 이미지 재검증 (S1 선택화면 / S2 결과 분리)
        │ Gate F   필드 연결표·조인·구현 방식 승인
[1]   DDIC 캐시 확인 → 부족분만 SE11 수집            │ Gate 1 ★빈칸 시 코드 금지
[2]   스펙 확정                                     │ Gate 2 "OK" 전 코드 금지
[3]   코드 생성 (골격 복제 → 세션 값 교체)            │ Gate 3 자동 점검 오류 0건
[4]   활성화 → 실행 테스트 → 오류 회수·수정           │ Gate 4 결과 회수 전 이관 금지
[5]   운영 이관 → 패턴·DDIC 캐시 승격
```

- 전 구간이 **AI가 묻고 담당자가 답하는 형식** (설계 25문항 + 검증·이관 12문항 = 37문항)
- 담당자는 양식을 작성하지 않음. 모르는 항목은 `[모름]`으로 넘김

## 10. 개선 방법 — Gate 3 자동 점검기

```text
$ python3 tools/abap_check.py sessions/.../code.abap
  ERROR  L47  CHK-005  사전 필드 `VBAK-...`를 참조하는데 `TABLES vbak.` 선언이 없습니다.
                       근거 ERR-006 · 처방: 코드 상단에 `TABLES <테이블>.` 선언을 추가하십시오.
  ERROR  L92  CHK-004  SELECT 직후 `SY-SUBRC` 체크가 없습니다.
요약: 파일 1개 · 오류 2건 · 경고 0건
Gate 3 미통과 — 오류 0건이 될 때까지 코드를 사용자에게 제시하지 마십시오.
```

- 17개 규칙 — `SELECT *`·루프 내 SELECT·`FOR ALL ENTRIES` 빈 체크·`SY-SUBRC`·`TABLES` 선언 등
- 지적마다 **근거 패턴 ID + 처방 한 줄** → 결과를 그대로 AI에 돌려주면 수정됨
- 소요 **0.04초**. 기계가 판별 못하는 항목은 "사람 판단"으로 명시 분리
- 자체 테스트 32항목으로 점검기 자체의 신뢰성 보증

## 11. 개선 방법 — 오류가 자산이 되는 경로

```text
① 활성화 실패 발생
      ↓ 오류 전문 회수 (양식 고정)
② practice/error-patterns.md 패턴 승격 (ERR / MSG / PROC)
      ↓ 기계 판별 가능하면
③ tools/abap_check.py 규칙 추가 → 코드 제시 전 자동 차단
      ↓ 모든 신규 프로그램에 해당하면
④ templates/abap/ 코드 골격 선반영 → 애초에 그렇게 생성됨
```

- 실제 사례: `SELECT-OPTIONS FOR eban-badat` 에 `TABLES eban.` 누락 → 활성화 실패
  → `ERR-006` 패턴 → `CHK-005` 규칙 → 골격 3종 선반영
- **현재 동일 오류는 담당자에게 전달되기 전에 기계가 차단**

## 12. 개선 효과 — 주효과: AI 활용 (① → ②)

실전 1호 산출물 기준, **담당자가 직접 작성하지 않게 된 분량**입니다.

| 지표 | ① AI 미활용 | ② AI 활용 |
|---|---|---|
| 착수 조건 | 대상 테이블을 알아야 착수 | 테이블 `[모름]` 상태에서 착수 |
| 테이블 선정 | SE11·업무 문서 직접 탐색 | AI가 후보 **6개** 제안 → 확인 |
| ABAP 소스 | **156줄** 전량 수작업 | AI 생성 (실효 122줄) |
| 선택화면 설계 | 항목·검증 규칙 직접 결정 | AI가 항목 4개 + 검증 3종 제안 |
| 테스트 설계 | 케이스·테스트값 직접 작성 | AI가 T1~T3 작성 |
| 운영 이관 문서 | 권한 조사·TR·잡 판단 직접 | AI가 권한·TR 초안·판정 작성 |
| 세션 문서화 | 별도 작성(또는 미작성) | 설계~검증 기록 **76줄** 자동 |
| 1건 소요 공수 | **[실측 기입]** | **[실측 기입]** → §15 계산식 |

- 핵심은 분량이 아니라 **착수 가능성** — 테이블·빈도·권한 전부 `[모름]`에서 운영 이관까지 완주
- 활성화 오류가 실효 122줄 중 **1건** → 수정 왕복 없이 거의 바로 쓸 수 있는 수준

| 운영 이관 | 권한 목록·TR 초안·배치잡 판정까지 완료 |
| 승격 자산 | `ERR-006` · `MSG-002` · `PROC-001` 3건 등록 |

- **데모가 아니라 실제 시스템에 활성화되어 운영 이관까지 끝난 건**

## 14. 개선 효과 — 부가효과: 저장소 가이드 (② → ③)

AI를 **그냥** 쓰는 것과, **방향을 주고** 쓰는 것의 차이입니다.

| 지표 | ② AI 단독 | ③ AI + 저장소 가이드 |
|---|---|---|
| 품질 검증 | 담당자 눈 검토 (8항목) | 17규칙 기계 점검 · **0.04초** |
| 검증 누락 | 기억·집중도 의존 | 종료코드로 강제 차단 |
| 요구사항 확인 | 코드 제시 후 교정 | 화면 목업·필드표 승인(Gate D/F) |
| DDIC 환각 | 모르는 필드를 지어냄 | 확정값만 사용 · `[확인필요]` |
| 출력 완전성 | 일부 생략 가능 | 복붙 계약으로 완전 소스 강제 |
| 오류 진단 | **1차 오진단 발생** | 패턴 조회로 즉시 식별 |
| 경험 축적 | 세션 종료 시 소멸 | 패턴 10 + 규칙 17 + 골격 3 |

**결함 발생률 — 같은 실수가 사라졌다**

| 구분 | 산출물 | ERR-006 보유 |
|---|---|---|
| 가이드 선반영 **전** (AI 단독 생성) | 2건 | **2건 (100%)** |
| 가이드 선반영 **후** (골격 기반) | 3건 | **0건 (0%)** |

- 사람이 수개월 몰랐던 **기준 샘플 잠복 결함**을 점검기 도입 즉시 검출

## 15. 개선 효과 — 절감 측정 방식 (주축)

기준선은 **AI 미활용(수작업) 공수**, 비교군은 **AI 활용 공수**입니다.

```text
① 1건 절감 공수 = [AI 미활용 공수] − [AI 활용 공수]
② 절감률(%)     = ① ÷ [AI 미활용 공수] × 100
③ 연간 절감 공수 = ① × 연간 건수
④ 연간 절감 금액 = ③ × 시간당 인건비
⑤ 재작업 회피   = (AI 미활용 재시도 − AI 활용 재시도) × 1회 왕복 공수 × 연간 건수
```

- AI 활용 활성화 재시도 **1회**(실측), 코드 생성 후 요구사항 재작업 **0회**(실측)
- AI 미활용 공수·연간 건수·인건비는 사내 실측값 필요 → `report/effect-worksheet.md`에 기입
- **측정 주의**: AI 활용 공수에 인터뷰 응답 시간을 포함해야 함 (빼면 절감 과대 계상)

## 16. 확산 가능성

확산 대상은 **"AI를 활용해 ABAP을 개발하는 방식"**, 저장소는 그 방식의 **전달 매체**입니다.
가이드가 파일로 존재하므로 구두 전수나 교육 없이 복제됩니다.

| 확산 축 | 재사용 자산 | 추가 필요 작업 |
|---|---|---|
| 모듈 (SD·MM·FI·PP) | 규칙·절차·점검기·골격 전부 | 모듈별 DDIC 캐시 축적 |
| 인원 (같은 팀) | 저장소 전체 | 없음 — Cursor로 열면 규칙 자동 적용 |
| 유형 (Module Pool·Interface 등) | 요구사항 템플릿 5종 보유 | 유형별 코드 골격 추가 |
| 부문 (타 SAP 개발 조직) | 규칙·절차·점검기 | 네이밍·패키지·권한 규칙 교체 |
| 도구 (Cursor 미사용) | 규칙 전문 + 프롬프트 조각 | 해당 도구에 지침 등록 |

- 사내 고유 정보가 **3개 파일로 격리** — 시스템 컨텍스트 / DDIC 캐시 / 오류 패턴
- SAP 외 영역 이식 가능: "AI가 직접 실행할 수 없고 사람이 결과를 옮기는" 업무면 동일 설계 적용

| 단계 | 내용 | 완료 기준 |
|---|---|---|

  표준 기록 항목을 넣으면 이후 세션부터 절감 효과가 자동 집계됨
