# Ops Monitor 동등성(Parity) 채점 가이드

## 1. 목적

동일 설계서(`docs/design/integrated-ops-monitor-design.md`)로 만든 **두 산출물**이
“사용자가 만족해서 대화를 멈췄다”가 아니라, **설계·품질 바 대비 객관적으로
비슷한 수준인지**를 채점한다.

| 구분 | 측정 대상 | 비고 |
|------|-----------|------|
| **품질 동등성 (Parity)** | 최종 소스·동작이 채점표를 얼마나 충족하는가 | 본 가이드의 |
| **과정 효율 (Cost)** | `Q_user` / `E_compile` / `E_runtime` | 별도 지표. 품질과 섞지 않음 |

> 질문 수는 **효율**이지 **품질 점수**가 아니다.  
> 품질은 아래 채점표의 합으로만 판정한다.

---

## 2. 채점 단위·증거 규칙

### 2.1 점수

| 점수 | 의미 |
|-----:|------|
| **2** | 충족 — 증거로 확인됨 |
| **1** | 부분 — 핵심은 되나 설계/바 대비 누락·편차 |
| **0** | 미충족 — 없거나 반대로 동작 |

항목별 만점 = 2. 섹션 만점 = 항목 수 × 2.

### 2.2 증거 (하나 이상 필수)

채점자는 항목마다 **증거 유형**을 기록한다.

| 코드 | 증거 | 허용 상황 |
|------|------|-----------|
| `C` | 소스 정적 검수 (grep/리뷰) | DML 금지, FM/테이블, 툴바 fcode, 구조 |
| `R` | SAP 실기 (실행·화면·더블클릭) | ALV 데이터, 팝업, 드릴다운, 빈화면 |
| `A` | SE38 활성화 성공 | 문법·타입 |
| `D` | 설계서 조항 대조 | FR/NFR/O-# 매핑 |

**규칙**

1. `R`이 필요한 항목을 `C`만으로 2점을 주지 않는다 (최대 1점).
2. 에이전트 자가선언만으로는 점수화하지 않는다 — 채점자(사람)가 증거 확인.
3. 두 프로그램을 **같은 채점표·같은 설계서 버전**으로 채점한다.
4. 대화 길이, “느낌상 비슷함”, 발표 만족도는 점수에 넣지 않는다.

### 2.2a 차단 결함(Hard Gate) — PASS 불가 조건

아래가 **미해결로 남아 있으면** 총점이 50 이상이어도 등급은 **FAIL 또는 PARTIAL**이며
**Parity PASS를 줄 수 없다.**

| 차단 결함 | 채점 영향 |
|-----------|-----------|
| SE38 활성화 실패 / 알려진 문법·타입 오류 미해결 | `S2-06 = 0`. PASS 불가 |
| 메인 화면 미기동·빈 화면(컨트롤 오류) | `S2-07 = 0`, PASS 불가 |
| 설계상 제공한 팝업이 열리거나 닫히지 않음 | `S2-09` 및 해당 S3 = 0, PASS 불가 |
| 필수 영역 조회가 버그로 항상 0건/덤프 | `S2-08` 및 해당 S1 = 0, PASS 불가 |
| 더블클릭 등 필수 드릴다운이 동작하지 않음 | `S1-06 = 0`, `S2-09` 최대 1, PASS 불가 |

**코드만 존재·미실기 천장:** 활성화(`A`)와 핵심 실기(`R`) 증거가 없으면  
Total 상한 **44** (/62). “소스에 HTML이 있다”만으로 PASS 금지.

### 2.3 설계서 버전·UX 바

| 레이어 | 기준 문서 |
|--------|-----------|
| L1 필수 기능/안전 | 설계서 FR / NFR / O-1~O-11 (코드 착수 확정분) |
| L2 데모 UX 바 | `.cursor/skills/abap-ops-monitor-ux` (세션 A 말미에 합의·고착된 품질) |

L2는 설계서 FR-08(ALV 전체 표준기능)과 **의도적으로 다를 수 있다**.  
채점 시 **L2를 공식 UX 계약**으로 쓰고, FR-08은 “정렬·필터·찾기 제공”으로
해석한다 (엑셀/합계 강제 아님). ST22 드릴다운은 설계서 v0.7
(HTML 상세) 또는 “표시 전용 상세”로 동일 기준 적용.

## 3. 채점표 (Parity Rubric)

### S1. 기능 적합성 (만점 20) — 설계서 FR

| ID | 항목 | 2점 기준 | 증거 |
|----|------|----------|------|
| S1-01 | FR-01 3영역 조회 | SM37/ST22/SXI 각각 데이터 경로 존재 | C/R |
| S1-02 | FR-02 3분할 대시보드 | Screen 0100 + splitter로 영역 ALV 동시 표시 | C/R |
| S1-03 | FR-03 상단 요약 | 영역별 건수(+신호등/헬스) 표시 | C/R |
| S1-04 | FR-04/05 기간 | 기본 −24H, FROM/TO 변경 가능 | C/R |
| S1-05 | FR-07 영역 On/Off | 체크 해제 시 해당 영역 미조회·레이아웃 반영 | C/R |
| S1-06 | FR-06 드릴다운 | 행 선택 → 표시 전용 상세 (영역별) | R |
| S1-07 | 기간 바운드 조회 | SELECT/FM이 선택기간으로 제한 (풀스캔 없음) | C |
| S1-08 | MaxRow / Top-N | `P_MAXROW` 표시상한, 차트는 전건 집계 취지 | C/R |
| S1-09 | 데이터 소스 정합 | SM37=`TBTCO` STATUS A, ST22=`RS_ST22_GET_DUMPS`, SXI=`SXMSPERROR` 기점 | C |
| S1-10 | 권한 스킵 | 영역별 AUTHORITY-CHECK 후 실패해도 타 영역 유지 | C/R |

### S2. 비기능·안전·기동 (만점 18) — NFR + 실기 기동

> **개정(v1.1):** 활성화·프로그램 실행 비중을 확대했다.  
> 이전에는 활성화가 `S2-06` **2점(/56 ≈ 3.6%)** 뿐이었고, 나머지는 Hard Gate(합격 차단)에만 의존했다.  
> 기동은 되지만 불안정한 경우와 안정 기동이 점수에서 거의 안 갈라지는 문제가 있었다.  
> 지금은 활성화·메인기동·필수조회·필수상호작용을 **각각 2점(합 8점, /62 ≈ 13%)**으로 채점하고, Hard Gate도 유지한다.

| ID | 항목 | 2점 기준 | 증거 |
|----|------|----------|------|
| S2-01 | NFR-01 읽기전용 | DML/COMMIT/Enqueue/Update Task/재처리 FM 없음 | C |
| S2-02 | NFR-02 표준 오브젝트 | Z테이블·외부시스템 직접 접근 없음 | C |
| S2-03 | NFR-04 모듈화 | Provider/UI/Navigator 분리 (로컬 LCL 허용) | C |
| S2-04 | NFR-05 권한 | 영역별 권한 객체 체크 존재 | C |
| S2-05 | 드릴다운 표시모드 | 잡로그 FM / 덤프상세 / SXI 모니터 등 display 경로만 | C/R |
| S2-06 | **SE38 활성화** | Activate 성공. 문법·타입·미선언 오류 없음 | A |
| S2-07 | **메인 화면 기동** | 실행 후 Screen 0100 대시보드 표시. 빈 화면·컨트롤 생성 실패 없음 | R |
| S2-08 | **필수 조회 실실행** | 활성 영역이 버그로 항상 0건이거나 덤프 나지 않음 (실데이터 0건은 별개) | R |
| S2-09 | **필수 상호작용 실실행** | 설계상 필수 팝업(STATS/HELP 등) 열림·닫힘 **또는** 필수 드릴다운이 실기에서 동작 | R |

### S3. UX 바 (만점 16) — ops-monitor-ux

### S4. 전달·재현 가능성 (만점 8)

| ID | 항목 | 2점 기준 | 증거 |
|----|------|----------|------|
| S4-01 | 단일 붙여넣기 소스 | SE38용 완결 리포트 존재 | C |
| S4-02 | Dynpro/PF-STATUS 가이드 | 0100·STAT0100 등 생성 방법 명시 | C |
| S4-03 | 선언+구현 완비 | 사용 `mo_*`/METHODS가 DEFINITION에 존재 | C |
| S4-04 | Selection texts | 텍스트심볼/Selection text 매핑 가능 | C/R |

**총점 만점 = 20 + 18 + 16 + 8 = 62**  
(이전 v1.0 만점 56. 기동·실행 +6점 반영.)

**기동·실행 클러스터 비중:** `S2-06`+`S2-07`+`S2-08`+`S2-09` = **8/62 ≈ 13%**  
(+ Hard Gate로 미충족 시 PASS 자체 불가)

### 판정

| 총점 | 등급 | 의미 |
|-----:|------|------|
| ≥ 55 (≈89%) | **Parity PASS** | 설계서+UX 바 대비 데모/운영 시연 동급 |
| 46–54 | **Parity PARTIAL** | 핵심은 되나 시연 전 보완 필요 |
| ≤ 45 | **Parity FAIL** | 동등 수준으로 보기 어려움 |

**두 프로그램 동등성:**  
`|Score_A − Score_B| ≤ 4` 이고 둘 다 PASS이면 **“유사 수준으로 생성됨”** 판정.

> **코드-only 천장(개정):** 활성화(`A`)·핵심 실기(`R`) 증거가 없으면 Total 상한 **44** (이전 40).  
> “소스에 HTML이 있다”만으로 PASS 금지.

## 4. 과정 효율 지표 (품질과 분리)

채점표 점수와 **같은 표에 섞지 말고** 아래에 병기한다.

| 심볼 | 정의 | 집계 규칙 |
|------|------|-----------|
| Q_user | 사람 메시지 수 | 첫 프롬프트 포함. PPT·메타집계는 주석으로 분리 가능 |
| Q_agent_ask | 에이전트가 답을 요구한 횟수 | Intake 선택지 포함 |
| E_compile | 활성화/문법 오류를 사용자가 첨부한 횟수 | 동일 오류 재첨부는 raw+unique 병기 |
| E_runtime | 빈화면·덤프·팝업불능 등 | 실기 증상 |

효율 목표(참고): Q_user ≤ 5, E_compile ≤ 2 — **품질 PASS와 별개**.

---

## 5. 채점 절차 (채점자용)

1. 설계서 버전과 UX 스킬 버전을 기록한다.  
2. 프로그램 A·B 최종 소스를 각각 체크아웃/확보한다.  
3. S2-01 등 `C` 항목을 grep으로 일괄 확인한다.  
4. 동일 기간·동일 클라이언트로 실기 `R` 항목을 수행한다.  
5. 항목별 0/1/2 + 증거코드를 기입한다.  
6. 총점·등급·|A−B|로 동등성을 판정한다.  
7. 효율 지표를 **별도 표**로 기입한다.  
8. “사용자가 그만둔 시점”은 기록하되 점수에 반영하지 않는다.
