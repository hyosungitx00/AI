# 인터뷰 스크립트 — AI 질문으로 설계해 나가는 단계별 Q&A (신규 기본)

> 신규 세션의 기본 진행 방식이다. 사용자가 작성 틀 전체를 한 번에 채우지 않고,
> AI가 아래 단계별로 한 턴에 최대 3문항씩 질문하고 답변을 받아 프로그램을 설계한다.
> AI는 이 스크립트를 순서대로 따르고, 단계를 건너뛰지 않는다.

## 진행 규칙 (AI용)

0. 세션 시작 질문(1~8문항) 종료와 같은 턴에 I-0부터 인터뷰를 자동 시작한다. 별도의 시작 요청 문구를 기다리지 않는다.
   `[신규 프로그램 요구사항 인터뷰 시작 요청]` 문구는 세션 시작 질문을 건너뛰었거나 인터뷰를 중단 후 재시작할 때만 쓰는 예비 수단이다.
1. 한 턴에 최대 3문항까지만 질문한다. 4문항 이상을 한 번에 묻지 않는다.
   모든 질문은 사용자가 타이핑 없이 클릭만으로 답할 수 있는 선택지형 자동 질문으로 제시한다.
   주관식 항목(목적·기능·항목 나열 등)도 반드시 후보 선택지 + `[모름]`·`건너뛰기`·`기타(직접 입력)`를 함께 제시하고,
   직접 타이핑을 필수로 요구하지 않는다. `기타` 선택 시에만 한 줄 입력을 받는다.
2. 매 답변에 `[모름]`·`건너뛰기`·`기본값으로 진행`을 허용한다. `[모름]`이면 AI가 제안·가정(`[추정]` 표시)으로 메우고 다음으로 넘어간다.
3. 각 단계가 끝나면 3줄 이내 단계 요약을 보여주고 `다음으로 넘어갈까요? (OK/수정)` 확인을 받는다. 확인 전에는 다음 단계로 가지 않는다.
4. `I-0`부터 순서대로 진행한다. 사용자가 "한 번에 입력할게요"라고 하면 `requirements/00-intake-prompt.md` 틀로 전환한다.
5. 인터뷰 전체가 끝나면 Gate U 이해도 확인서를 제시하고, 이후 08-demo → Gate D → 09-fieldmap → Gate F → Gate 2 순으로 이어간다.

## 단계별 질문

### I-0 접수 (1턴)

1. `신규 vs 변경`: 신규 프로그램인가요, 기존 변경인가요? (변경이면 기존명 + 변경점 한 줄)
2. `화면 데모`: 참고할 화면 데모(그림·HTML·엑셀·설명)가 있나요? [있음 / 없음-AI 생성]
3. `희망 유형`: 원하는 형태가 있나요? [01 ALV / 02 화면 / 03 함수 / 04 강화 / 05 연동 / 06 배치 / 07 서식 / 모름-AI 판단]

### I-1 한 줄 요약 (1턴, 최대 3문항)

4. `목적`: 이 프로그램이 해결할 일을 한 줄로 말씀해 주세요. (예: 영업조직별 판매실적을 엑셀 없이 조회)
5. `사용자·빈도`: 누가, 얼마나 자주 쓰나요? (모르면 "모름")
6. `기존 대체`: 대체하는 기존 T-code·프로그램이 있나요? (없으면 "없음")

### I-2 핵심 기능 (1~2턴)

7. `핵심 기능 ①`: 가장 중요한 기능 1가지를 말씀해 주세요. (예: 판매조직+생성일로 조회)
8. `핵심 기능 ②~`: 추가로 필요한 기능을 번호로 이어서 말씀해 주세요. (없으면 "없음", 예: 결과 ALV·VA03 이동·엑셀 다운로드)
9. 확인: `지금까지 기능이 ①…②…③… 맞나요? 빠진 것이 있으면 번호로 추가해 주세요.`

### I-3 입력 조건 (1턴, 최대 3문항)

10. `입력 항목`: 화면에서 입력할 조건은 무엇인가요? (예: 판매조직 필수·생성일 범위)
11. `기본값`: 자주 쓰는 기본값이 있나요? (예: 판매조직 1000·당월)
12. `입력 검증`: 틀리게 입력하면 어떻게 해야 하나요? (예: 시작일>종료일 에러 / 모름)

### I-4 출력 형태 (1턴, 최대 3문항)

13. `출력 형태`: 결과는 어떤 모양인가요? [조회 ALV / 입력 후 저장 / 외부 전송·파일 / 출력 서식]
14. `출력 항목`: 보여주거나 저장할 항목을 나열해 주세요. (예: 판매문서·생성일·고객·순매출)
15. `출력 동작`: 결과에서 눌러서 넘어가는 동작이 있나요? (예: 판매문서 클릭→VA03 / 없음)

### I-5 화면 데모 (분기)

- 데모 있음 → 16a. `화면 설명`: 데모 화면을 하나씩 설명해 주세요. (화면명·입력칸·버튼·누르면 일어나는 일) 첨부 위치도 함께 주세요. (예: 파일 p.2)
- 데모 없음 → 16b. AI가 I-1~I-4 답변으로 텍스트 목업을 생성해 보여주고 `화면이 맞나요? (컨펌/수정)` 확인을 받는다. 텍스트 컨펌 후 화면 데모 이미지를 생성해 한 번 더 검증을 받는다 (Gate D-2). 실행가능 리포트(SE38)는 선택화면과 ALV를 한 화면에 합치지 않고 S1 선택화면 / S2 ALV 결과로 분리한다 (합성형은 Module Pool로 오인됨).

### I-6 데이터·기존 정보 (1턴, 모르면 전부 건너뛰기 가능)

17. `후보 테이블`: 아는 테이블·필드가 있나요? (예: VBAK-VBAP / 모름)
18. `조인·조건`: 아는 조인·추출 조건이 있나요? (예: VBELN 조인·주문 유형만 / 모름)
19. `기존 함수`: 재사용할 함수·BAPI가 있나요? (예: 없음 / 모름)

### I-7 권한·예외·제약 (1턴, 최대 3문항)

20. `권한`: 아는 권한 오브젝트가 있나요? (예: V_VBAK_VKO / 모름-SU53 예정)
21. `0건·실패 시`: 데이터가 없거나 실패하면 어떻게 보여줄까요? (예: "데이터가 없습니다" / AI 제안 요청)
22. `개인정보·제약`: 개인정보가 포함되나요? 실데이터 첨부 금지(코드값만)에 동의하시나요? [미포함·동의 / 포함-마스킹 / 모름]

### I-8 테스트값 (1턴, 최대 3문항)

23. `T1 정상`: 대표 입력값 1개를 주세요. (예: VKORG=1000)
24. `T2 0건`: 빈 결과가 나오는 값 1개를 주세요. (예: VKORG=9999 / AI 제안 요청)
25. `T3 권한·검증`: 권한 없음·입력 오류 값을 주세요. (예: VKORG=2000 / 해당 없음)

## 코드 제공 이후 인터뷰 (Verify·Handover — 끝까지 질문 형식)

코드 제공 후에도 사용자가 자유 형식으로 보고하지 않고, AI가 아래 단계별로 질문하고 답변을 받아 마무리한다.
"활성화 OK + T1~T3 결과" 회수 전까지 Handover로 가지 않는다 (Gate 4 유지).

### V-1 활성화 확인 (1턴, 최대 3문항)

26. `Syntax Check`: SE38에서 `Ctrl+F2` 결과는? [에러 0건 / 에러 있음(기타란에 행번호+메시지 전문)]
27. `Extended Check`: 확장 검사 결과는? [Error 0건 / 있음(기타란에 내용)]
28. 에러 있으면 → V-3 오류 회수 질문으로 분기, 없으면 V-2로 진행.

### V-2 실행 테스트 (1턴, 최대 3문항)

29. `T1 정상`: 대표값 실행 결과는? [정상 ALV 표시 / 덤프·오류 발생(기타란에 증상)]
30. `T2 0건`: 빈 조건 실행 결과는? [규정 메시지 표시 / 다르게 동작(기타란에 내용)]
31. `T3 권한·검증`: 권한·검증 실패 실행 결과는? [규정 메시지 / 다르게 동작 / 해당 없음]

### V-3 오류 회수 (오류 발생 시만, 1턴, 최대 3문항)

32. `덤프·메시지`: ST22 덤프명(예: ITAB_DUPLICATE_KEY) 또는 메시지 전문을 기타란에 그대로 붙여넣어 주세요.
33. `입력값·위치`: 어느 케이스(T1/T2/T3) 입력값인가요? Syntax 에러면 행번호는요?
34. `SY-SUBRC`: 디버깅(`/BREAK-POINT`) 확인값이 있나요? (없으면 "없음")
- 회수 후 AI는 `practice/error-patterns.md`를 먼저 대조한다. 기존 패턴 ID가 있으면 그 ID의 처방으로 답하고,
  없으면 새 ID(ERR/MSG/PROC-nnn)로 패턴을 추가한 뒤 답한다 (V-3 승격 규칙).
  덤프 대응표는 `error-patterns.md` ERR 표와 동일하게 유지한다.

### V-3b 다건 Syntax 오류 접수 (에러 2건 이상일 때)

- ABAP Syntax 오류는 연쇄(cascade)되므로 **첫 번째 1건부터 순차 해결**한다. 전체를 한 번에 받지 않는다.
- 접수 방식 (사용자가 택1):
  - (A) 첫 1건만: 기타란에 `행번호 + 메시지 전문` 1건 기입 → AI 수정본 → 재검사 → 다음 1건 (반복)
  - (B) 목록 파일: 세션 폴더에 `errors.md`(아래 양식)로 정리해 파일 첨부 → AI가 위에서부터 1건씩 순차 수정
  - (C) 화면 캡처: SE38 오류 목록 화면 스크린샷 첨부 → AI가 판독해 1건씩 순차 수정

```markdown
# errors.md 양식 (세션 폴더에 저장)
| # | 행번호 | 메시지 전문(복붙) | 상태 |
|---|---|---|---|
| 1 | 000045 | ... | 수정 대기 |
| 2 | 000078 | ... | 대기 |
```

### V-4 Verify 확정

- "활성화 OK + T1~T3 정상"이 모두 모이면 `Verify 확정 — Handover로 넘어갈까요? (OK/수정)` 확인을 받는다. 확인 전에는 Handover 산출물을 만들지 않는다.

### H-1 운영 이관 (1턴, 최대 3문항)

35. `T-code`: 신규 T-code가 필요한가요? [필요(희망 코드 기입) / 불필요(SE38 실행)]
36. `권한 확정`: SU53 TRACE 결과 이상 없나요? [이상 없음 / 오브젝트 추가 필요(기타란에 기입)]
37. `이송·잡`: 이송 희망일과 배치잡 등록 여부를 알려주세요. (예: 2026-__-__ / 잡 불필요)
- 답변 후 AI가 Handover 묶음(SE93 안내·권한 목록·TR 초안·운영 주의사항)을 제공한다.
- 마지막 질문: `이관 묶음이 맞나요? (완료/수정)` — 완료 답을 받아야 세션 종료.

## 인터뷰 종료 후 (AI용)

1. 전 단계 답변을 모아 Gate U 이해도 확인서(목적·기능·입출력·예외·모호점·데모 분기)를 제시한다.
2. 사용자가 `OK`하면 08-demo(Gate D 텍스트 컨펌 → Gate D-2 이미지 재검증) → 09-fieldmap(Gate F) → 유형 템플릿 구조화 → Gate 2 순으로 진행한다.
3. 인터뷰 중 `[추정]`으로 메운 항목은 이해도 확인서에 모아 다시 점검받는다.
4. 코드 제공 후에는 V-1 → V-2 (오류 시 V-3) → V-4 → H-1 순으로 끝까지 질문 형식으로 마무리한다.
