# 업무 시스템 한 페이지 브리핑 (타 AI 인계용)

> **용도**: 이 저장소를 처음 접하는 다른 AI에게 "무슨 시스템에서 무슨 일을 하는가"를 1페이지로 전달한다.
> **이 문서는 사실만 담는다.** 지켜야 할 행동 규칙은 `harness/prompts/system-prompt-fragment.md`에 있다.
> 그대로 복사해 다른 AI 대화 맨 앞에 붙여넣어도 된다.

## 1. 한 줄 정의

SAP GUI 환경의 커스텀 ABAP 개발을, **AI가 SAP에 접속할 수 없다는 전제**로 수행하는 작업 체계.
AI는 코드를 쓰고, 사람이 SE38/SE37에 복붙해 활성화한다. AI는 자기 코드가 도는지 볼 수 없다.

## 2. 대상 시스템

| 항목 | 값 | 상태 |
|---|---|---|
| 시스템 | SAP S/4HANA On-Premise | 확정 |
| 릴리스 | `SAP_BASIS 750` | 확정 (기준선) |
| ABAP 문법 상한 | 7.50+ 모던 허용 — `@` 호스트변수, 인라인 `DATA()`, `VALUE #()`, `COND #()`, `FILTER` | 확정 |
| ECC 호환 모드 | 사용자가 **명시 요청한 건에만** 보수적 문법으로 하향 | 확정 |
| ALV 방식 | 건별 선택 — `CL_SALV_TABLE` / `REUSE_ALV_GRID_DISPLAY` / `CL_GUI_ALV_GRID` | 확정 |
| 주석 | 한국어 + 영문 병기 (`... / ...`) | 확정 |
| 네이밍 | `Z + 모듈약어 + _ + 기능`(예: `ZMM_PR_LINK_ALV01`) · 함수그룹 `ZFG+모듈` · 클래스 `ZCL_+기능`<br>`ZTEST*` `ZTEMP*` `ZZZZ*` 금지 — TADIR 등록 가능한 실명만 | 확정 |
| 패키지 | 실적 1건 `ZMM01` · `$TMP` 금지 | 건별 확인 |
| 클라이언트 / TR 규칙 / 메시지 클래스 / 권한 TRACE 가능 여부 | **미확정** — `context/system-context.template.md`를 채워야 함 | 미확정 |

## 3. 대상 업무

| 유형 | 내용 | 트랜잭션 | 범위 |
|---|---|---|---|
| 01 ALV 리포트 | 선택화면 + 조회 + ALV 출력 | SE38 | **주력** |
| 03 Function Module | 재사용 로직, 배치 호출 대상 | SE37 | **주력** |
| 02 / 04~07 | Module Pool · Enhancement · Interface · Batch · Forms | SE80 등 | 확장 (요구사항 템플릿만 보유) |

대표 요청은 "여러 화면을 돌며 눈으로 맞춰 보던 정보를 한 화면에서 조회하게 해 달라"는 조회성 리포트다.
보조 트랜잭션: SE11(DDIC) · SE16N(데이터) · SE91(메시지) · SE93(T-code) · SU21/PFCG(권한) ·
ST22(덤프) · SU53(권한 트레이스) · SM36(배치잡).

## 4. 절대 제약 — 어기면 작업이 실패한다

1. **SAP 직접 접근 없음.** 코드는 생략 없는 완전 소스로, 복붙 즉시 활성화 가능해야 한다.
   실행·활성화·디버깅을 했다고 **말하지 않는다**. 항상 "SE38에서 아래 값으로 테스트하십시오" 형태로 전달한다.
2. **DDIC 환각 금지.** 테이블·필드는 사용자가 확인해 준 값, 또는 `context/ddic-cache.md`의 `확정` 행만
   사용한다. 모르는 필드는 추측 코드 대신 `[확인필요]` 주석 + 질문으로 되돌린다. 가정 3건 초과 시 코드 생성 중단.
3. **릴리스 게이트.** 코드 상단에 `"! 기준: SAP_BASIS 750 / S/4HANA, 모던 ABAP 허용` 명시.
4. **묻지 않는 것** — SAP 접속 정보(호스트·클라이언트·ID·PW), 실제 운영 데이터.
   테스트는 마스킹 코드값(예: `10000001`)으로 충분하다.
5. **세션 격리** — 새 세션에서 이전 **세션 폴더**(`sessions/`)의 요구사항·설계·코드를 끌어오지 않는다.
   예외는 시스템에서 확인된 *사실*인 `context/ddic-cache.md`의 `확정` 행뿐이다.

## 5. 작업 절차 — 승인 없이 다음 산출물을 만들지 않는다

```text
Gate 0  사전준비(릴리스·패키지·네이밍) → Gate U  AI 이해도 확인서 승인
Gate D  화면 텍스트 목업 컨펌 → Gate D-2  화면 이미지 재검증(선택화면 S1 / 결과 S2 분리)
Gate F  필드 연결표·조인·구현 방식 승인 → Gate 1  DDIC 확정(1칸이라도 비면 코드 금지)
Gate 2  미니 스펙 사용자 "OK" (「바로 코드 줘」 요청에도 불응) → Gate 3  코드 + 자동 점검 오류 0건
Gate 4  활성화·T1~T3 결과 회수 → Handover  T-code·권한·TR → 패턴·DDIC 캐시 승격
```

접수는 **인터뷰 전용**이다. 양식 일괄 입력·자유 텍스트·파일 첨부는 받지 않고 인터뷰로 전환한다.
질문은 한 턴 최대 3문항, 총 37문항. 사용자는 `[모름]`으로 넘길 수 있고 AI가 제안 후 `[추정]`으로 표시해 재확인한다.

## 6. 현재 확정된 사실 (DDIC)

| 범위 | 내용 |
|---|---|
| 확정 | `EBAN` — BANFN, BNFPO, BADAT, WERKS, EKGRP (활성화 성공으로 실재 증명) |
| 미확인 (사용 금지) | `EBKN` `EKPO` `MSEG` `RSEG` `VBAP` — SE11 확인 필요 |
| 예시 전용 (업무 사용 금지) | `examples/` · `templates/abap/`의 `VBAK` `VBAP` `KNA1` — 문서용 더미 |

캐시는 **실재(필드가 있다)만 보증**한다. 조인 방향·업무 의미는 세션마다 Gate F에서 다시 확인한다.
캐시의 침묵은 "존재하지 않음"도 "존재함"도 아니다. AI는 자기 지식으로 캐시 행을 추가하지 않는다.

## 7. 품질 기준 — 사람 기억이 아니라 기계가 본다

```bash
python3 tools/abap_check.py <파일>     # Gate 3 필수. 오류 0건 전에는 코드를 사용자에게 제시하지 않음
```

규칙 17개(`CHK-001`~`017`): `SELECT *`, 루프 내 SELECT, `FOR ALL ENTRIES` 빈 체크, `SY-SUBRC`,
`TABLES` 선언, 릴리스 문법, 헤더·부록, 주석 병기 등. 지적마다 근거(패턴 ID)와 처방 한 줄이 붙어,
출력을 그대로 AI에 돌려주면 수정된다. 기계가 못 보는 것(없는 필드, 조인의 업무 타당성, 화면 구조
오인)은 **"사람 판단"으로 분리** 표기되어 있다.

## 8. 축적된 함정 (실제로 당한 것)

| ID | 내용 |
|---|---|
| ERR-006 | `SELECT-OPTIONS ... FOR eban-badat` 쓰면서 `TABLES eban.` 누락 → 활성화 실패. **가장 자주 재발** |
| ERR-005 | 선택화면 전체 미입력 허용 → 전건 조회 과부하. 미입력 차단 필요 |
| PROC-001 | SE38 실행 리포트 화면 목업을 선택화면+ALV 합성 1장으로 제시 → 반려. **S1/S2 분리 필수** |
| PROC-002 | 0건인데 성공처럼 보임 → `SY-SUBRC` 체크 + 메시지 + `RETURN` 필요 |
| MSG-002 | 사용자가 SE91 생성을 원하지 않으면 텍스트 리터럴 메시지로 전환 |

전체 10건은 `practice/error-patterns.md`. 오류는 **패턴 → 점검 규칙 → 코드 골격** 순으로 승격되어
다음부터는 애초에 그렇게 생성된다.

## 9. 코드 전달 형식 (복붙 계약) — 코드가 포함된 답변의 필수 구성

① 생략 없는 완전 소스 1개 → ② 번호 매긴 복사 순서(트랜잭션 명시) → ③ DDIC·메시지·T-code 정의서
→ ④ T1(정상) / T2(0건·예외) / T3(권한·검증) 테스트 표 → ⑤ 오류 회수 양식

코드는 `templates/abap/` 골격에서 시작해 `TODO(교체)` 마커를 전부 치환한다. 마커 잔류 = 미완성.
