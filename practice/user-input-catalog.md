# 사용자에게 받아야 하는 데이터·질문 총정리

> 근거: `SKILL.md` §3.1 (환각 금지 — 테이블·필드는 사용자가 준 것만 사용), `SKILL.md` §3.3 (복붙 계약),
> `harness/prompts/session-start.md` (세션 시작 8문항), `harness/prompts/interview-script.md` (인터뷰 37문항),
> `context/ddic-collect.template.md` (DDIC 수집 양식)
>
> 이 문서는 "AI가 혼자 알아낼 수 없어서 반드시 사용자에게 받아야 하는 것"만 모은 목록이다.
> 질문 **문장**은 `harness/prompts/interview-script.md` 가 정본이고, 이 문서는 **무엇을·어디서·어떻게 받고, 없으면 어떻게 하는지**를 정리한다.

## §0 왜 이 목록이 필요한가

AI는 SAP 시스템에 접속할 수 없다. SE11을 열 수도, 프로그램을 실행할 수도, 권한 추적을 걸 수도 없다.
그래서 산출물 품질은 **사용자가 가져다주는 입력의 정확도에 그대로 좌우된다.**

받지 못한 입력을 AI가 추측으로 메우면 두 가지 중 하나가 일어난다.

| 추측한 대상 | 결과 |
|---|---|
| 업무 규칙 (소계 기준·기본값 등) | 활성화는 되지만 **원하는 결과가 아닌 프로그램**이 나온다. 되돌리는 비용이 크다 |
| 시스템 실측값 (테이블·필드명 등) | 활성화 단계에서 **구문 오류**로 막힌다. 되돌리는 비용은 작지만 왕복이 늘어난다 |

후자가 전자보다 낫다. 그래서 업무 규칙은 **끝까지 묻고**, 시스템 실측값은 `[확인필요]` 로 격리한 뒤 진행할 수 있다.

## §1 입력을 얻는 방법으로 나눈 3구분

| 구분 | 성격 | 사용자가 하는 일 | 받는 시점 |
|---|---|---|---|
| **A. 업무 지식** | 사용자 머릿속에 있다 | 질문에 말로 답한다 | 세션 시작 ~ Gate F |
| **B. 시스템 실측** | SAP 화면을 열어야 보인다 | SE11·SE16N 등을 열어 **값을 복사해 붙여넣는다** | Gate F 전 (코드 생성 전) |
| **C. 실행 결과** | 돌려봐야 나온다 | 코드를 붙여넣고 실행한 뒤 **결과를 회신한다** | Gate 4 (코드 제공 후) |

A는 없으면 `[추정]` 으로 메우고 Gate U에서 다시 점검한다.
B는 없으면 `[확인필요]` 로 격리하되, **3건을 넘으면 코드 생성을 중단하고 Gate 1로 돌아간다** (`HARNESS.md` §3.2).
C는 대체 수단이 없다. 받지 못하면 Gate 4를 닫을 수 없다.

## §2 구분 A — 업무 지식 (말로 답하는 입력)

질문 문장은 `harness/prompts/interview-script.md` I-0~I-8 (1~25번)에 있다. 아래는 **받아야 하는 값**의 관점으로 다시 묶은 것이다.

| # | 받아야 하는 값 | 왜 필요한가 | 없을 때 |
|---|---|---|---|
| A-1 | 프로그램의 목적 한 줄 | 유형(ALV/화면/함수) 선택의 근거 | **생략 불가.** 이것 없이는 시작하지 않는다 |
| A-2 | 신규 / 기존 변경 여부 | 변경이면 기존 소스 회수가 선행된다 | 신규로 가정 |
| A-3 | 희망 프로그램 유형 | `requirements/01~07` 중 어느 틀을 쓸지 | AI가 A-1·A-6로 판단 |
| A-4 | 사용자·사용 빈도 | 성능 목표와 `p_maxrow` 류 상한의 근거 | `[추정]` 일 2~3회 |
| A-5 | 대체하는 기존 T-code | 표준 프로그램의 SELECT를 베낄 수 있다 (B-6의 지름길) | 없음으로 간주 |
| A-6 | 핵심 기능 목록 (번호로) | 스펙 §기능의 본문이 된다 | **생략 불가** |
| A-7 | 선택화면 입력 조건 | `SELECT-OPTIONS`·`PARAMETERS` 구성 | AI 제안 후 Gate D 확인 |
| A-8 | 입력 기본값 | `DEFAULT` 절 | 기본값 없음으로 생성 |
| A-9 | 입력 검증 규칙 | `AT SELECTION-SCREEN` 블록 | AI 제안 (예: 전건 조회 차단) |
| A-10 | 출력 형태 | ALV / 저장 / 전송 / 서식 중 택1 | A-1로 판단 |
| A-11 | 출력 항목 목록 | 필드카탈로그와 `TYPES` 의 원본 | AI 제안 후 Gate D 확인 |
| A-12 | 출력에서의 후속 동작 | 더블클릭 → 표준 T-code 호출 | 없음으로 간주 |
| A-13 | 집계·소계 기준 | 트리 단 구성, 소계 행 | **AI가 추측하면 안 된다.** 선택지를 주고 고르게 한다 |
| A-14 | 0건·실패 시 표시 문구 | 메시지 설계 | AI 제안 문구 |
| A-15 | 개인정보 포함 여부 | 출력 항목에서 이름류를 뺄지 결정 | **미포함 가정 + 코드값만** 원칙 적용 |
| A-16 | 테스트값 3종 (정상·0건·오류) | Gate 4 검증 시나리오 | AI 제안값 (실데이터 요구 금지) |

### A-13을 특별히 다루는 이유

이번 세션에서 "수량 소계를 어느 단에 붙일지"는 선택지 A/B/C를 제시하고 사용자가 `A` 를 골라 확정했다.
집계 기준은 **업무 해석의 문제**라서 AI가 고르면 틀릴 확률이 높고, 틀리면 트리 구조 전체를 다시 짜야 한다.
같은 성격의 항목(정렬 기준, 중복 제거 기준, 0 숨기기 기본값)은 모두 선택지를 만들어 고르게 한다.

## §3 구분 B — 시스템 실측 (SAP 화면을 열어 복사해야 하는 입력)

**이것이 이 저장소에서 가장 자주 막히는 지점이다.** 조회 경로를 항목마다 적어 둔다.

| # | 받아야 하는 값 | SAP 조회 경로 | 없을 때 |
|---|---|---|---|
| B-1 | SAP 릴리스 (SAP_BASIS) | 메뉴 `시스템` → `상태` → SAP_BASIS 행 | `[★기본값]` 750 / S4 |
| B-2 | 테이블 필드 목록 (Field·Data element·Type·Len·Dec) | `SE11` → 테이블명 → 표시 → `필드` 탭 | `[확인필요]` 격리, 3건 초과 시 중단 |
| B-3 | 키 필드 (조인키·WHERE 후보) | 같은 화면의 `Key` 체크 칼럼 | 추측 금지. 조인을 못 짠다 |
| B-4 | 체크·텍스트 테이블 | `SE11` → `외래키` 탭 | 내역 칼럼을 뺀 채 생성 |
| B-5 | 필드에 **실제 값이 들어 있는지** | `SE16N` → 테이블명 → 실행 → 1행 (개인정보 마스킹) | 치명적. S/4에서 빈 필드를 읽는 코드가 나온다 |
| B-6 | 표준 프로그램의 SELECT 구문 | `SE38` → 표준 프로그램명 → 표시 → 복사 (MB52는 `RM07MLBS`, MMBE는 `RMMMBESTN`) | B-2~B-5를 하나씩 묻는 긴 길로 돌아간다 |
| B-7 | 패키지 (개발클래스) | 사내 담당자 확인 / `SE80` | `[미정]`. `$TMP` 금지 안내만 한다 |
| B-8 | 메시지 클래스 존재 여부 | `SE91` → 클래스명 조회 | 텍스트 리터럴로 생성 (이번 세션 방식) |
| B-9 | TR(요청번호) 규칙 | 사내 규칙 / `SE09` | `[미정]`, Handover에서 재확인 |
| B-10 | 로그온 언어·한글 주석 입력 가능 여부 | GUI 로그온 화면 / 직접 타이핑 시도 | `[★기본값]` KO·한영 병기 |
| B-11 | 권한 오브젝트명 | `SU53` (실패 직후) / `SU21` | `TODO(SU21/SU53)` 주석으로 격리 |

### B의 가장 빠른 길 — B-6을 먼저 요청한다

표준 프로그램의 SELECT 한 덩어리는 B-2·B-3·B-4·B-5를 **한 번에** 해결한다.
그 시스템에서 실제로 동작하는 이름이므로 추측이 아닌 확정값이고, 사용자의 손도 덜 간다.
B-2를 테이블마다 묻기 전에 **B-6을 먼저 제안한다.**

### 그래도 테이블을 직접 확인해야 하면 — 점검 프로그램을 만들어 보낸다

이번 세션에서는 `SE11`을 대상마다 여는 대신 `ddic-probe.abap`(119행) 한 본을 만들어 보냈다.
점검 대상은 **16건**(테이블 14 + S/4 호환 뷰 2)이었고, 사용자는 **한 번 실행**해 실측값을 회수했다.
받아야 할 실측 항목이 5건을 넘으면 **점검 프로그램 작성을 우선 검토한다.**

점검 프로그램은 DDIC 메타데이터만 읽고 **업무 데이터를 바꾸지 않는다**는 점을 헤더에 명시하고,
"사용 후 삭제해도 된다"를 함께 적는다. 그래야 사용자가 운영 영향을 걱정하지 않고 실행할 수 있다.

| 방식 | 사용자 조작 횟수 | 선택 기준 |
|---|---|---|
| 질문으로 하나씩 | 항목 수만큼 | 1~4건 |
| `SE11` 화면 복사 | 테이블 수만큼 | 소수 테이블의 전체 필드가 필요할 때 |
| **점검 프로그램 1본** | 1회 | **5건 이상, 또는 "값이 실제로 있는지"(B-5)를 봐야 할 때** |

### 요청서는 빈칸 양식으로 만든다

실측 요청은 산문으로 쓰지 않고 **빈칸을 채워 회신할 수 있는 표**로 만든다
(예: `sessions/20260930-ZMM_STOCK_TREE01/ddic-request.md`). 산문으로 쓰면 일부 항목이 누락된 채 돌아온다.

## §4 구분 C — 실행 결과 (코드 제공 후 받아야 하는 입력)

질문 문장은 `harness/prompts/interview-script.md` V-1~H-1 (26~37번)에 있다.

| # | 받아야 하는 값 | SAP 조작 | 받는 형식 |
|---|---|---|---|
| C-1 | 구문 검사 결과 | `SE38` → `Ctrl+F2` | 에러 0건 / **행번호 + 메시지 전문 그대로** |
| C-2 | 확장 검사 결과 | `SE38` → `Ctrl+Shift+F2` | Error 0건 / 내용 |
| C-3 | 활성화 성공 여부 | `Ctrl+F3` | 성공 / 실패 사유 |
| C-4 | T1 정상값 실행 결과 | 실행 후 화면 | 정상 표시 / 증상 서술 (화면 캡처 권장) |
| C-5 | T2 0건 실행 결과 | 실행 후 화면 | 규정 메시지 / 다른 동작 |
| C-6 | T3 권한·검증 실행 결과 | 실행 후 화면 | 규정 메시지 / 다른 동작 |
| C-7 | 덤프명·메시지 전문 | `ST22` | **전문 그대로.** 요약하지 말 것 |
| C-8 | SU53 TRACE 결과 | 권한 실패 직후 `SU53` | 이상 없음 / 추가 오브젝트명 |
| C-9 | T-code 필요 여부·희망 코드 | — | 필요(코드) / 불필요 |
| C-10 | 이송 희망일·배치잡 등록 여부 | — | 날짜 / 불필요 |

### C-1·C-7은 "전문 그대로"가 핵심이다

요약된 오류 메시지로는 처방을 찾을 수 없다. 이번 세션의 오류 5건은 모두
`Line213 "GV_TIT1" was already declared.` 처럼 **행번호 + 원문**으로 받아서 1회 왕복에 해결됐다.

### 구문 오류가 2건 이상이면 첫 1건만 받는다

ABAP 구문 오류는 연쇄된다. 앞의 1건을 고치면 뒤의 여러 건이 함께 사라진다.
그래서 **첫 1건부터 순차 처리**한다 (`harness/prompts/interview-script.md` V-3b).

|---|---|---|

## §6 사용자가 "모름"이라고 답할 때

`harness/prompts/interview-script.md` 진행 규칙 2에 따라 `[모름]`·`건너뛰기`·`기본값으로 진행`은 항상 허용한다.
그 다음 처리가 구분마다 다르다.

| 구분 | 모름일 때 처리 | 표시 | 어디서 다시 점검하나 |
|---|---|---|---|
| A 업무 지식 | AI가 제안·가정으로 메우고 진행 | `[추정]` | Gate U 이해도 확인서에 모아 재점검 |
| B 시스템 실측 | 코드에서 격리하고 진행 | `"! [확인필요]` | Gate F 필드맵. **3건 초과 시 코드 생성 중단** |
| B-11 권한 | 체크 지점만 만들고 비워 둠 | `"! TODO(SU21/SU53)` | 활성화 후 SU53 실측으로 확정 |
| C 실행 결과 | **대체 불가.** 받을 때까지 Gate 4를 닫지 않는다 | — | V-4 Verify 확정 |

### `[확인필요]` 3건 초과 규칙을 면제받는 방법

이번 세션에서는 미확정 DDIC가 7건이어서 규칙 한도를 넘었다. 그때 AI는 **중단하고 선택지를 제시했다.**

- (A) 실측 회수 후 진행 — 정확하지만 한 번 더 왕복
- (B) 추측값으로 코드 받기 — 해당 줄마다 `[확인필요]` 주석, 구문 오류는 V-3b로 순차 수정

사용자가 (B)를 골랐고, 그 결과 오류 3건이 발생해 순차 수정됐다.
**면제는 사용자의 명시적 지시로만 가능하고, AI가 알아서 넘어가면 안 된다.**

## §7 절대 요구하지 않는 것 (보안 금지 목록)

받으면 안 되는 것을 명확히 해 둔다. 사용자가 먼저 주려 해도 받지 않는다.

| 금지 항목 | 이유 | 대신 하는 일 |
|---|---|---|
| 접속 정보 (호스트·클라이언트·ID·비밀번호) | AI는 접속하지 않는다. 받을 이유가 없다 | "SE38에서 아래 값으로 테스트하십시오" 로 안내 |
| 실데이터 첨부 | 개인정보·영업정보 노출 | **코드값만** 받는다 (`VBELN=0100000001` 형태) |
| 마스킹하지 않은 샘플 행 | 같음 | `홍길동 → H***` 마스킹 후 1행만 |
| 고객·공급업체 **이름** | 개인정보 | 번호만 출력 (이번 세션 I-7 답변으로 확정) |
| 운영 시스템 직접 작업 | 사고 위험 | 개발 클라이언트에서만 |

AI가 하지 않는 선언도 함께 지킨다. **"SAP에서 실행해 봤다"고 말하지 않는다.** 실행은 전부 사용자가 한다.
