# practice/ — 오류·교훈 패턴 축적 (세션 공유 지식)

> 프로그램 실행·활성화 오류와 설계 교훈 중 "다음 세션에서도 같은 답이 나올 것"을 패턴으로 쌓는다.
> AI는 **Gate 3 코드 생성 전(`code-review-checklist`와 함께) 이 파일을 반드시 확인**하고,
> 해당 패턴을 코드에 선반영한다. V-3에서 회수된 신규 오류는 아래 승격 규칙으로 추가한다.

## 파일

| 파일 | 내용 | 확인 시점 |
|---|---|---|
| `error-patterns.md` | 패턴 대장 — ERR / API / MSG / PROC 표 | Gate 3 전 전수 대조 |
| `screen-text-detail.md` | PROC-005·006 의 실행 기준 — SE51 화면·SE41 상태/타이틀·SE38 텍스트 요소 정의서의 **필수 목차와 서술 규칙** | 산출물에 Dynpro·선택화면이 있을 때 |
| `user-input-catalog.md` | 사용자에게만 받을 수 있는 입력 전수 — 업무 지식(A) / 시스템 실측(B) / 실행 결과(C) 3구분, SAP 조회 경로, 모름일 때 처리, 보안 금지 목록 | 인터뷰 시작 전 · 코드 생성 전 |

## 사용 규칙

1. Gate 3 전 확인: 코드 작성 전 `error-patterns.md` 전 항목을 대조하고, 해당 항목을 코드·주석에 반영한다.
2. V-3 승격: 오류 회수 시 기존 패턴 ID가 있으면 그 ID로 답하고, 없으면 새 ID(ERR-nnn / MSG-nnn / PROC-nnn)로 추가한다. **승격은 판단이 아니라 트리거다** — 아래 중 하나라도 발생하면 그 턴에 추가하고 `출처 세션` 을 적는다. 사용자에게 저장 여부를 묻지 않는다 (`GOVERNANCE.md` §1.3).

| 트리거 | ID |
|---|---|
| 구문·런타임 오류를 회수해 해결 | `ERR-nnn` |
| 클래스·함수 시그니처를 실측으로 확정 (유추가 틀렸던 경우) | `API-nnn` |
| **사용자가 같은 종류를 2회 이상 재요청** (AI 누락 신호 — 가치가 가장 크다) | `PROC-nnn` |
| 설계를 되돌림 (방식 A → B 전환) | `PROC-nnn` |
| 메시지·권한 처리 방식을 사용자가 지정 | `MSG-nnn` |
3. 한 패턴은 증상·원인·처방·사전방지 4행으로만 적는다 (장문 금지). 분량이 큰 실행 기준은 별도 파일로 빼고 패턴 행에서 링크한다.
4. GUI 수작업 산출물(화면·텍스트 요소)이 있으면 `screen-text-detail.md` §E 자가 점검을 답변 직전에 수행한다.
5. 사용자에게 무언가를 요청하기 전 `user-input-catalog.md` 를 확인한다. 실측 요청이 5건을 넘으면 질문 대신 점검 프로그램 1본을 검토하고(§3), 요청서는 빈칸 양식으로 만든다.

## 패턴 ID 규칙

- `ERR-nnn`: 덤프·Syntax·실행 오류 (예: ERR-001)
- `MSG-nnn`: 메시지·권한 처리 관행 (예: MSG-001)
- `PROC-nnn`: 데모·설계·진행 관행 (예: PROC-001)
