# 화면·텍스트 정의 답변 디테일 기준 (GUI 수작업 산출물)

> `error-patterns.md` **PROC-005 · PROC-006** 의 실행 기준.
> AI는 **Gate 3 코드 생성 전** 이 파일을 확인하고, 해당 산출물이 있으면 아래 목차를 전부 채운다.

## 0. 왜 별도 기준이 필요한가

`SKILL.md` §3.3 복붙 계약은 **소스 코드**만 다룬다. 그런데 아래 3종은 소스로 복붙할 수 없고 사용자가 SAP GUI 에서 손으로 만든다.

| 오브젝트 | T-code | 코드로 대체 가능? |
|---|---|---|
| Dynpro 화면 (요소 목록·흐름 로직) | SE51 / SE80 | 불가 |
| GUI 상태 · GUI 타이틀 | SE41 / SE80 | 불가 |
| 텍스트 요소 (선택 텍스트·프로그램 제목) | SE38 → 이동 → 텍스트 요소 | 불가 |

소스를 완벽하게 줘도 이 3종의 **입력값을 표로 주지 않으면 사용자는 화면을 만들 수 없다.**
"SE51 에서 화면 0100 을 만드십시오" 같은 한 줄 안내는 **복붙 계약 위반으로 취급한다.** 사용자는 어떤 요소를 어떤 유형으로 어떤 이름으로 둬야 하는지 알 수 없고, 질문 왕복이 2~3회 늘어난다.

## A. 화면(Dynpro) 정의서 — 필수 목차

산출물에 Dynpro 가 1개라도 생기면 `sessions/<세션>/screen-<화면번호>.md` 를 만들고 아래를 **전부** 채운다. 해당 없으면 "해당 없음 + 이유"를 적고, 항목 자체를 지우지 않는다.

| # | 항목 | 최소 디테일 |
|---|---|---|
| A-1 | 화면 개요 | 프로그램명 · 화면번호 · 짧은 설명 · 화면 유형 · **다음 화면** · 호출 지점 · 복귀 지점 · GUI 상태명 · 타이틀명 · 화면 개수 |
| A-2 | **요소 목록 (탭별)** | SE51 요소 목록의 **탭 단위 표**: 일반 속성(이름·유형·라인·칼럼·DLen·VisLen·Hght·수정그룹) / 텍스트·I/O 템플릿 / 특수 속성(기능코드·기능유형·입력·출력) / 표시 속성 · 수정 그룹 · 참조. 표에 없는 칼럼은 "전부 기본값"이라고 명시 |
| A-3 | 이름이 계약인 요소 | 요소명 ↔ 코드의 대응 줄(`container_name = '...'` 등) ↔ **불일치 시 증상** 3칼럼 표 |
| A-4 | 두지 않은 요소와 이유 | 푸시버튼·OK 코드 필드·프레임 등. "꼭 두고 싶다면" 대안 1행도 함께 |
| A-5 | GUI 상태 | 상태명 · 상태 유형 · **기능 키 표**(키 · 기능코드 · 기능유형 · 텍스트) · 메뉴 바 · 애플리케이션 툴바 처리 |
| A-6 | GUI 타이틀 | 타이틀명 · **텍스트 원문**(`&1` 치환 포함) · 치환값을 만드는 코드 · 실제 표시 예시 2개 이상 |
| A-7 | 흐름 로직 | PBO·PAI **전문**(주석 포함). `AT EXIT-COMMAND` 위치, `SET PF-STATUS`·`SET TITLEBAR` 를 분기 밖에 둬야 하는 이유 |
| A-8 | PBO 처리 순서 | 컨트롤 생성·갱신 순서를 번호로. 재호출 시 중복 생성 방지 분기 포함 |
| A-9 | 이벤트·전환표 | 사용자 조작 → 기능코드 → 처리 모듈 → 결과 |
| A-10 | 생성 절차 | 번호 매긴 GUI 조작 순서 (SE51 → SE41 → 활성화) |
| A-11 | 활성화 후 점검 체크리스트 | 체크박스 형식. "무엇이 보여야 정상인지" 기준으로 |
| A-12 | 오류 대응표 | 증상 → 원인 → 조치 |
| A-13 | 의도적으로 넣지 않은 것 | 항목 → 이유 |
| A-14 | 변경 이력 | 일자 · 내용 · 근거 |

## B. 텍스트 요소 정의서 — 필수 목차

선택화면이 있으면 사실상 항상 해당한다. `sessions/<세션>/text-elements.md` 를 만들고 아래를 채운다.

| # | 항목 | 최소 디테일 |
|---|---|---|
| B-1 | 텍스트 요소 4종 사용 여부 | 선택 텍스트 / 프로그램 제목 / 텍스트 심볼 / 리스트 머리글 **각각** 사용 건수. 0건도 "0건 + 이유"로 적는다 |
| B-2 | 유지보수 경로 | `SE38 → 이동 → 텍스트 요소 → ...` 전체 경로 + 저장·활성화 |
| B-3 | 사전 참조 사용 여부 판단 | 사전 참조 / 직접 입력 **장단점 표 + 채택안**. DDIC 참조 필드와 비참조 필드를 구분 |
| B-4 | **선택 텍스트 전수 표** | 선택화면 순서 · 이름 · **입력할 텍스트 원문** · 길이 · 사전 참조 on/off · DDIC 참조 · 필수 여부. `SELECT-OPTIONS` 와 `PARAMETERS` 를 블록별로 분리 |
| B-5 | 라벨 의미 | 현업이 읽을 1줄 동작 설명 (특히 체크박스·한계값 파라미터) |
| B-6 | 프로그램 제목 | 입력 위치 · 입력값 원문 · 길이 · 보이는 곳 |
| B-7 | 텍스트 심볼 처리 | `TEXT-xxx` 를 쓰는지. 안 쓰면 그 문구를 무엇으로 대체했는지(블록 제목 변수 등)와 근거 패턴 ID |
| B-8 | 점검 체크리스트 | 유지보수 화면에 행이 보이는지 → 저장했는지 → 실행 화면에 라벨이 보이는지 |
| B-9 | 오류 대응표 | 라벨이 필드명으로 보임 · 영문으로 보임 · 비어 보임 · 잘림 각각의 원인·조치. **텍스트 요소 문제가 아닌 증상**(블록 제목·창 제목)도 구분해 적는다 |
| B-10 | 의도적으로 넣지 않은 것 | 번역(SE63) · F1 커스텀 문서 · 변형 저장 등 |

## C. 서술 규칙 (A·B 공통)

1. **입력값은 원문 그대로 적는다.** "적절한 이름" · "알맞은 크기" 금지. 그대로 타이핑할 수 있는 값만 적는다.
2. **이름이 계약인 것과 아닌 것을 분리한다.** "이름과 유형만 정확해야 하고 위치·크기는 무해하다"처럼 틀려도 되는 범위를 명시해 사용자의 부담을 줄인다.
3. **생략 가능 / 불가를 명시한다.** 생략 가능한 항목은 "건너뛰어도 기능에 영향 없음"이라고 쓴다. 반대로 GUI 상태·타이틀처럼 **생략하면 실사용 불가**인 것은 그 사실을 굵게 적는다 (PROC-005).
4. **릴리스 차이는 미리 완화한다.** 항목·버튼 이름이 릴리스마다 다른 경우 "릴리스에 따라 이름이 다르다"를 붙인다. 추측한 명칭을 단정하지 않는다.
5. **표에 없는 칼럼은 기본값**이라고 한 번 선언한다. 수십 개 칼럼을 모두 적지 않아도 되게 만드는 장치다.
6. **변경 이력**에 "왜 이 항목이 추가/변경됐는지" 근거(패턴 ID·사용자 지적)를 남긴다.
7. 세션 `spec.md` §복사 순서에 **SE51·SE41·텍스트 요소 단계를 번호로 끼워 넣고**, 상세는 이 두 문서로 링크한다.
8. 프로그램 소스 헤더 주석에 **필요 오브젝트 목록**(①SE38 ②SE51 ③SE41 상태 ④SE41 타이틀 ⑤텍스트 요소)과 요약 생성 절차를 넣는다. 소스만 본 사람도 할 일을 알 수 있어야 한다.

## D. 하지 말 것

| 금지 | 대신 |
|---|---|
| "SE51 에서 화면을 만드세요" 한 줄 안내 | A-2 요소 목록 표 |
| 선택 텍스트를 "선택 사항(optional)" 으로 처리 | B-4 전수 표. 라벨 없는 화면은 미완성이다 |
| GUI 상태·타이틀 생략해 SE41 작업 회피 | A-5·A-6. 푸시버튼으로 대체하면 F3·Shift+F3·F12 가 모두 죽는다 (PROC-005) |
| 요소 목록을 요소 1개만 적고 "나머지는 기본값" | 요소가 1개뿐이면 그 사실을 "요소는 1개뿐이다"로 단정해 적는다 (무엇을 안 만드는지도 정보다) |
| 화면·텍스트 정의를 코드 답변 안에 섞어 묻히게 하기 | 세션 폴더에 별도 `.md` 로 분리 + 코드 헤더에서 링크 |
