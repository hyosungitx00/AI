# 00-INTAKE — 신규 세션 요구사항 접수 커버 (인터뷰 전용 안내)

> 모든 신규 세션은 인터뷰(I-0~I-8)로 접수한다. 이 커버의 §2 (B) 작성 틀·(C) 자유 텍스트·파일 경로는 더 이상 접수하지 않으며, 해당 입력이 오면 인터뷰로 전환한다.
> 인터뷰 시작은 아래 한 줄만 보내면 된다.

```text
[신규 프로그램 요구사항 인터뷰 시작 요청]
```

## §0 접수 정보 ★ (인터뷰 I-0에서 구두로 확인 — 미리 작성 불필요)

- 세션 유형 ★: [ ] 신규 프로그램 [ ] 기존 프로그램 변경(기존명: ____)
- 화면 데모 ★: [ ] 있음(I-5에서 설명) [ ] 없음(AI가 생성 → Gate D에서 확인)
- 희망 프로그램 유형(추정, 몰라도 됨): [ ] 01 ALV [ ] 02 ModulePool [ ] 03 Function [ ] 04 Enhancement [ ] 05 Interface [ ] 06 Batch [ ] 07 Forms [ ] 모름(AI 판단에 맡김)

## §2 요구사항 접수 방식 ★ (인터뷰만 허용)

- (A) 인터뷰 방식(유일): 사용자가 따로 작성하지 않는다. AI가 `harness/prompts/interview-script.md` 순서(I-0 접수 → I-8 테스트값, 한 턴 최대 3문항)로 질문하고 답변을 받아 설계한다. 첫 마디로 아래 한 줄만 보내면 시작된다.

```text
[신규 프로그램 요구사항 인터뷰 시작 요청]
```

- (B) 작성 틀 한 번에 / (C) 자유 텍스트·파일: 접수 중단(2026-09-29). 해당 입력이 오면 인터뷰 I-0으로 전환한다. `requirements/00-intake-prompt.md`는 참고용으로만 보관한다.

## 접수 후 AI 동작 (사용자는 읽지 않아도 됨)

1. 인터뷰 I-0 → I-8 답변을 모아 Gate U — "AI가 이해한 내용"(목적·사용자·핵심 기능·입력/출력·예외·모호점)을 정리해 점검받는다. 승인 전에는 다음 단계로 가지 않는다.
2. 데모 분기 — 데모 있음 → `08-demo.md` 분석 경로 / 데모 없음 → AI 데모 생성 경로(`08-demo.md`). 텍스트 목업 컨펌(Gate D) 후 데모 이미지로 한 번 더 확인받는다(Gate D-2).
3. 화면 컨펌 후 — `09-fieldmap.md`(필드 연결 정보 + 구현 방식)를 작성해 점검받는다(Gate F).
4. Gate F 승인 후 — 기존 흐름의 해당 유형 템플릿(01~07)으로 구조화 → Gate 2 스펙 확정 → Gate 3 코드.
