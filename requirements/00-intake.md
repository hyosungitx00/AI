# 00-INTAKE — 신규 세션 요구사항 접수 안내 (답변지 전용)

> 모든 신규 세션은 답변지 I 1건으로 접수한다. AI가 `harness/prompts/session-answer-sheet.md` 블록을 제시하면 채워서 통째로 붙여넣는다.
> 작성 틀·자유 텍스트·파일 경로는 더 이상 접수하지 않으며, 해당 입력이 오면 답변지 I로 전환한다.
> 작성 예시는 `examples/filled/session-answer-sheet.filled.md`.

## §0 접수 정보 ★ (답변지 I에서 확인 — 미리 작성 불필요)

- 세션 유형 ★: [ ] 신규 프로그램 [ ] 기존 프로그램 변경(기존명: ____)
- 화면 데모 ★: [ ] 있음(I-5에서 설명) [ ] 없음(AI가 생성 → Gate D에서 확인)
- 희망 프로그램 유형(추정, 몰라도 됨): [ ] 01 ALV [ ] 02 ModulePool [ ] 03 Function [ ] 04 Enhancement [ ] 05 Interface [ ] 06 Batch [ ] 07 Forms [ ] 모름(AI 판단에 맡김)

## §2 요구사항 접수 방식 ★ (답변지 I만 허용)

- (A) 답변지 방식(유일): AI가 답변지 I 블록 1개를 제시하면 아는 칸만 채워 통째로 붙여넣는다. 빈칸·`[모름]`은 AI가 `[추정]` 제안으로 메우고 Gate U에서 확정받는다. 한 문항씩 묻지 않는다. 작성 예시는 `examples/filled/session-answer-sheet.filled.md`.

- (B) 작성 틀 한 번에 / (C) 자유 텍스트·파일: 접수 중단(2026-09-29). 해당 입력이 오면 답변지 I로 전환한다. `requirements/00-intake-prompt.md`는 참고용으로만 보관한다.

## 접수 후 AI 동작 (사용자는 읽지 않아도 됨)

1. 답변지 I 1건 답변을 모아 Gate U — "AI가 이해한 내용"(목적·사용자·핵심 기능·입력/출력·예외·모호점)을 정리해 점검받는다. 승인 전에는 다음 단계로 가지 않는다.
2. 데모 분기 — 데모 있음 → `08-demo.md` 분석 경로 / 데모 없음 → AI 데모 생성 경로(`08-demo.md`).
3. 화면 컨펌 후 — `09-fieldmap.md`(필드 연결 정보 + 구현 방식)를 작성해 점검받는다(Gate F).
4. Gate F 승인 후 — 기존 흐름의 해당 유형 템플릿(01~07)으로 구조화 → Gate 2 스펙 확정 → Gate 3 코드.
