# 00-INTAKE — 신규 세션 요구사항 접수 커버 (텍스트·파일)

> 신규 세션의 첫 입력용 커버이다. **기존 요구사항을 참조할 필요가 없으며**, 세션마다 이 커버 + 요구사항 본문(텍스트 붙여넣기 또는 파일)으로 시작한다.
> 접수 후 AI는 코드를 만들지 않고 Gate U(이해도 확인)부터 진행한다.

## §0 접수 정보 ★

- 세션 유형 ★: [ ] 신규 프로그램 [ ] 기존 프로그램 변경(기존명: ____)
- 요구사항 형식 ★: [ ] 채팅 텍스트 붙여넣기 [ ] 파일 첨부(형식: md / txt / xlsx / docx / pdf / 이미지 / html 데모)
- 첨부 파일명: [예: 요구사항_판매실적조회_v1.md / 없으면 "없음-텍스트"]
- 화면 데모 포함 여부 ★: [ ] 있음(아래 §1 기입) [ ] 없음(AI가 생성 → Gate D에서 확인)
- 희망 프로그램 유형(추정, 몰라도 됨): [ ] 01 ALV [ ] 02 ModulePool [ ] 03 Function [ ] 04 Enhancement [ ] 05 Interface [ ] 06 Batch [ ] 07 Forms [ ] 모름(AI 판단에 맡김)

## §2 요구사항 접수 방식 ★ (택1 — 기본은 인터뷰)

- (A) 인터뷰 방식(기본·권장): 사용자가 따로 작성하지 않는다. AI가 `harness/prompts/interview-script.md` 순서(I-0 접수 → I-8 테스트값, 한 턴 최대 3문항)로 질문하고 답변을 받아 설계한다. 첫 마디로 아래 한 줄만 보내면 시작된다.

```text
[신규 프로그램 요구사항 인터뷰 시작 요청]
```

- (B) 작성 틀 한 번에: `requirements/00-intake-prompt.md` 틀을 복사·작성해 그 블록 1개를 붙여넣는다. 작성 예시는 `examples/filled/00-intake-prompt.filled.md`.
- (C) 자유 텍스트·파일: 요구사항 전문을 그대로 붙여넣거나 파일(md/txt/xlsx/docx/pdf/이미지/html 데모)을 첨부하고 본문은 `[파일 참조]`라고 적는다. 보충 설명이 있으면 한 줄로 추가한다.

## 접수 후 AI 동작 (사용자는 읽지 않아도 됨)

1. Gate U — 요구사항을 분석해 "AI가 이해한 내용"(목적·사용자·핵심 기능·입력/출력·예외·모호점)을 정리해 점검받는다. 승인 전에는 다음 단계로 가지 않는다.
2. 데모 분기 — 데모 있음 → `08-demo.md` 분석 경로 / 데모 없음 → AI 데모 생성 경로(`08-demo.md`).
3. 화면 컨펌 후 — `09-fieldmap.md`(필드 연결 정보 + 구현 방식)를 작성해 점검받는다(Gate F).
4. Gate F 승인 후 — 기존 흐름의 해당 유형 템플릿(01~07)으로 구조화 → Gate 2 스펙 확정 → Gate 3 코드.
