## 1. 요약 (Executive Summary)

1,479행 ABAP 소스와 2,999행 세션 문서를 산출한 SE38 ALV 트리 리포트 1건이 **대화 43턴 / 커밋 22건 / 커밋 기준 실작업 4시간 34분**(달력 경과 27시간)에 완료됐다. 사용자는 SAP 접속·테스트만 담당했고 AI는 접속 없이 설계·코드·화면 정의를 생산했다.

왕복 43턴 중 **설계를 전진시킨 턴은 31턴(72%)**, **오류 회수 5턴(12%)**, **AI 측 정의 누락으로 발생한 재요청 4턴(9%)**, **순손실 3턴(7%)**(단순 재출력 요청)이다. 누락형 4턴은 전부 AI 기준 미비였고, 7건의 재사용 패턴으로 등록해 재발 경로를 닫았다.

동일 산출물을 개발/운영팀이 AI 없이 만들었을 경우 **약 65 man-hour(범위 40~100h)** 로 추정한다. 현재 하네스 상태에서 같은 프로그램을 다시 만들면 **약 3 man-hour**로 추정한다. 비율은 보수적으로 **14~20배**다. 단, 이 수치는 09-22 ~ 09-29 동안 선행 투입된 하네스 구축 비용(공통 자산 2,214행, 커밋 25건)을 상각 대상에서 제외한 값이다.

## 8. 결론

1. **구조가 작동한다.** 1차 세션의 ERR-005·006 이 2차 세션 코드에 선반영돼 재발하지 않았다. `sessions/` 는 격리하고 `practice/` 로만 지식을 넘기는 설계가 의도대로 기능했다.

2. **남은 비효율은 한 곳에 몰려 있었다.** 회수 왕복 9건 중 4건(44%)이 "코드로 복붙할 수 없는 GUI 수작업 오브젝트(SE51/SE41/텍스트 요소)를 요약 안내로 처리"한 단일 원인이었다. PROC-005·006 등록과 Gate 3 체크리스트 연결로 이 경로를 닫았다.

3. **추측을 코드에 넣지 않은 판단이 가장 크게 기여했다.** 사용자가 "B 추측값으로 코드 받기"를 택했을 때 점검 리포트를 선행시킨 결과 `확인필요` 3건이 0건이 됐다. `MSKU`·`MSLB` 의 보류 필드 부재와 `MARD`/`MKOL` 이중 계상은 추측으로는 맞힐 수 없었고, 그대로 코드에 들어갔다면 덤프 또는 **조용히 틀린 수량**이 됐을 것이다. 후자가 훨씬 위험하다.

4. **AI 가 못 하는 일이 명확하다.** SAP 접속·활성화·실행·화면 작성은 전부 사용자 몫이었다. 단축 배수는 "AI 가 개발자를 대체한 배수"가 아니라 **"설계·코딩·문서화를 AI 가 맡고 사용자가 SAP 조작과 판단에 집중했을 때의 배수"** 다.

5. **다음 개선 지점.** 오류 5건 중 3건이 ALV 컨트롤 API 시그니처였다. 표준 데모 프로그램(`BCALV_TREE_*`)의 파라미터 관례를 `practice/` 에 1회 회수해 두면 추측형 왕복을 더 줄일 수 있다. 현재 API-001 은 `CL_GUI_ALV_TREE` 1개 클래스만 다룬다.
